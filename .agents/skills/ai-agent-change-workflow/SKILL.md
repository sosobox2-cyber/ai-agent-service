# AI Agent Service 변경 워크플로

프로젝트 경계·보안·단일 에이전트 정책과 검증 범위는 [AGENTS.md](../../../AGENTS.md)를 따른다. 같은 규칙을 재분석하거나 모든 참고 문서를 일괄 열지 않는다.

## 진행

1. 현재·기대 동작과 완료 조건을 정하고 실제 호출 경로에서 영향 범위를 확인한다. 문서 변경은 관련 문서만 확인한다.
2. 승인 결과·보안·외부 계약·공통 검증·외부 전송·비용에 따라 위험을 판단한다. 높은 위험은 구현 전에 영향, 실패 시 결과, 안전한 검증 방법과 회귀 범위를 정한다.
3. 최소 범위로 수정하고 관련 검증을 실행한다. 통과한 검증은 변경·실패·미해결 위험이 추가되지 않으면 반복하지 않는다. 실패는 변경 결함·환경·기존 문제로 구분한다.
4. 최종 diff를 요구사항·검증 결과와 대조해 자체 검토하고 기존 사용자 변경 보존을 확인한다. 범위가 넓어지면 위험과 검증 계획을 다시 판단한다.
5. 작은 변경은 최종 답변에 변경·검증·미검증 결과만 남긴다. 보고서가 필요한 경우 [보고서 규칙](../../../docs/report/report-guide.md)에 따라 작업당 한 파일에 통합한다.

## 변경별 연관 확인

| 변경 | 확인할 범위 |
|---|---|
| DTO·API | 입력 보정, 오류 HTTP 상태, API 문서·예제·화면 요청 |
| 최종 판정·검증 | certain, 전체·개별 confidence, 반려 제안, 빈 결과, 단위·단품 조합 |
| 프롬프트·AI 파싱 | LIGHT/FULL, 실제 입력, Schema·파싱·버전, 재추론 상한 |
| 모의 추출 | 실제 AI 경로 분리, TEST_MODE와 자동 적용 불가 |
| usage·이력 | 호출별·합계 usage, 미측정 값, elapsedMs, inferenceId, 정보 노출 |
| 웹 화면 | 요청·예제·단위 입력·결과 표시와 관련 Node 회귀 |
| 인증·설정 | 운영 기본값, 키 부재, 요청 제한, 테스트 격리 |
| 평가 하네스 | 입력 해시·trialId·중복 방지, 예산·미측정 usage, 기준·검토 이력·백업 |
