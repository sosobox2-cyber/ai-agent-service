# 스토아 운영상품 테스트

IntelliJ에서 **AI Agent Service** 실행 후 `http://127.0.0.1:8081/evaluation.html`에 접속한다. 개발·테스트는 이 로컬 서버를 기준으로 한다. 실행 설정 변경 후에는 Stop → Run으로 재시작한다.
메인 화면의 **스토아 운영상품 테스트**에서 테스트 창을 열 수 있다. 목록에서 상품을 실행하거나 상세를 열어 결과·원문·요청·응답·토큰 사용량을 확인한다. 창 오른쪽 상단의 X 버튼으로 닫는다. 메인 입력란으로 상품을 옮기는 버튼은 제공하지 않는다.

각 실행은 실제 요청 입력도 함께 저장하고 원본 샘플은 유지한다. 상세의 요청 JSON은 선택한 실행 당시 입력을 보여준다. 과거 버전의 실행처럼 입력 기록이 없는 경우 원본 샘플을 표시한다. 실행 API에서 수정 입력을 전달할 경우 상품 ID가 다르면 실행을 막아 다른 상품에 이력이 섞이지 않게 한다. 메인 화면에서 직접 입력하거나 기본 예제로 실행한 결과는 일반 추론 API와 호출 로그를 사용하며 관리 사례를 자동 생성하지 않는다.

## 데이터 가져오기와 보관

전달한 파일은 **전달한 샘플 데이터 불러오기** 버튼으로 바로 열 수 있다. 같은 파일이 이미 등록되어 있으면 기존 데이터 세트와 테스트·검토 이력을 그대로 사용한다. 처음 불러오는 서버에서만 새로 가져온다. 실제 AI 호출은 발생하지 않는다.
로컬 원본은 `data/evaluation-samples/sample.xls`에 두며 Docker에서 읽기 전용으로 연결한다. 파일은 Git과 이미지 빌드에서 제외된다. 파일 내용을 바꾸면 이전 자료를 덮어쓰지 않고 새 데이터 세트를 만든다.

`구매옵션 정보2.xls`와 같은 열 구성을 가진 `.xls`·`.xlsx` 파일을 업로드한다. 최대 파일 크기는 32MB, 최대 행 수는 100,000이다.
`SQL Results` 시트가 있으면 사용하고, 없으면 첫 시트를 사용한다. 첫 행은 다음 열 이름을 포함해야 한다.

`상품코드`, `상품명`, `스토아CAT`, `정보고시`, `기술서`, `단품코드`, `색상_사이즈명`, `단품상세`, `구매옵션명`, `필수옵션단위`, `옵션단위`, `구매옵션 정답`

- 상품코드로 요청을 묶고 단품코드로 원본 단품을 묶는다. 단품상세를 추론 입력으로 사용하고 색상_사이즈명은 검토용으로 보존한다.
- 원본 Excel 행 번호, 파일명, 파일 SHA-256, 가져온 시각을 보관한다. 빈 기준값과 서로 충돌하는 기준값은 확인 표시를 남긴다.
- 상품 공통 입력 또는 단위 설정이 충돌하거나 API 입력 제한을 넘는 상품은 실행을 막고 상세에 이유를 표시한다.
- Excel의 원본 등록값은 수정하지 않는다. 재업로드는 기존 이력을 덮어쓰지 않고 새 데이터 세트를 만든다.
- Docker의 `evaluation-data` 볼륨에 데이터·실행 이력·검토 변경 이력을 저장한다. 컨테이너 재생성 후에도 유지된다. `docker compose down -v`는 해당 볼륨을 삭제하므로 데이터 백업을 먼저 받는다.
- **데이터 백업**은 원본을 해석한 입력, 기준 행, 모든 실행 결과와 검토 변경 이력을 ZIP으로 내려받는다. ZIP 복원 UI는 현재 제공하지 않는다.

## 실행과 비교

상품코드·상품명·카테고리, 진행 상태, 구매옵션명으로 검색할 수 있다. 실행할 상품을 선택한 뒤 실행한다. 한 번에 최대 20상품을 순서대로 요청한다.

실행 모드는 **실제 AI**로 고정되어 있다. 실행 버튼을 누르면 서버 운영 키로 과금 호출한다.
모드 선택과 별도 비용 확인란 없이 공급자 API를 호출한다. 요청당 LIGHT/FULL 재추론이 일어날 수 있으며 실제 사용량은 상세의 응답에서 확인한다.
다음 사례로 넘어갈 때 2.5초 간격을 두며, 오류 발생 시 배치를 중지한다. 중지 버튼은 현재 요청을 마친 뒤 다음 사례부터 중단한다.
브라우저를 닫으면 새 요청을 보내지 않지만, 서버에서 이미 시작한 요청은 완료되어 저장될 수 있다. 배치 자동 재개는 제공하지 않는다.

비교 상태는 동일, 표현만 다름, 불일치, 결과 없음, 기준값 없음, 중복 결과로 구분한다.
공백·대소문자·전각 문자 차이와 단일 수치의 무게·용량·길이 환산만 동등하게 본다. `개`와 `매` 등 다른 개수 단위를 임의로 같은 것으로 취급하지 않는다.
비교 결과의 '일치'는 정답 확정이나 자동 적용 승인이 아니다. 서버가 반려한 AI 제안도 상세에 표시하지만 성공 처리할 수 없다.

## 사람의 검토와 회귀

1. 사례 상세에서 원문·단품·기준값·실행값·추론 근거를 비교한다.
2. 서버가 승인한 **실제 AI 결과**를 검토한 뒤 행별 **성공 확인** 체크박스를 누른다.
3. 해당 실행값이 별도 확정 기준값으로 저장된다. 원본 등록 기준값은 유지된다.
4. 다음 실행에서는 확정값과 비교하며 달라지거나 결과가 없어지면 회귀를 표시한다.
5. 새 실행 결과는 다시 검토해야 한다. 이전 실행의 체크를 그대로 새 결과의 성공으로 사용하지 않는다.

**검토 / 교정**에서 시스템 개선 필요, 등록 기준값 확인 필요, 검토 메모를 저장할 수 있다.
등록값이 잘못됐다고 판단하면 교정한 확정 기준값과 메모를 함께 남긴다. 이 값은 다음 실행부터 비교에 사용된다.
검토 초기화는 해당 행의 검토 상태와 확정값을 해제한다. 이전 실행 및 검토 변경 이력은 백업에 남는다.
이전 실행 이력은 조회용이며 검토 저장은 최근 실행에서만 가능하다. 다른 실행이 먼저 완료됐으면 오래된 화면의 검토 저장을 거부한다.

## 실행 설정

- 평가 API는 `EVALUATION_ENABLED=true`일 때만 켜진다. 로컬 `compose.yaml`에 설정되어 있으며 운영은 기본 비활성이다.
- IDE에서 쓰려면 이 환경 변수와 `EVALUATION_DATA_DIRECTORY`를 지정한 뒤 서버를 재시작한다. 기본 저장 위치는 `data/evaluation`이며 Git에서 제외된다.
- IDE와 Docker는 기본 저장소가 서로 다르다. 이 버전의 파일 저장소는 한 서버 인스턴스에서 사용하는 것을 전제로 한다.
- 로컬 Docker가 `127.0.0.1`에만 공개된 경우 샘플 불러오기·조회·가져오기·검토·백업·모의 실행·실제 AI 실행에는 키 입력이 필요 없다. 실제 AI는 서버에 설정된 공급자 운영 키를 사용한다. 기존 추론 API와 외부 서버 접속에는 기존 `X-API-Key` 인증을 유지한다.
- 로컬 예외는 `EVALUATION_LOCAL_UI_ENABLED=true`와 루프백 게시 주소가 함께 설정된 경우에만 켜진다. Compose는 `HOST_ADDRESS`를 실제 게시 주소와 `EVALUATION_LOCAL_BIND_ADDRESS`에 동일하게 전달한다. 주소가 `0.0.0.0` 등 외부용이면 예외는 꺼진다. 다른 출처의 브라우저 요청도 로컬 예외에서 제외한다.
- 테스트 관리 화면에는 키 입력란이 없다. 공급자 운영 키는 서버에서만 사용하며 브라우저에 전달하지 않는다. 실행 버튼을 누르면 실제 AI를 호출한다.
- 로컬 모의 실행은 별도 `mock-runs` 경로에서 서버가 모의 모드를 강제한다. 요청 본문으로 실제 AI 모드로 바꿀 수 없다.
- 목록 조회·가져오기·검토 저장은 추론 요청 한도를 소비하지 않는다. 실행 요청에는 기존 요청 한도를 적용한다.
- 서버에 데이터를 업로드하는 기능이므로 로컬 용도로 사용한다. 운영 공개·다중 사용자·다중 서버 저장소 전환은 별도 작업이다.
