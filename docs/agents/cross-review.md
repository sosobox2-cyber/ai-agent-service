# 교차 리뷰

## 목적과 원칙

요구사항, 최종 diff와 테스트 근거를 대조해 오승인·누락·정보 노출·운영 비용 위험을 찾는다. 테스트 통과나 모델 confidence만으로 정답을 가정하지 않는다. 구현을 수행한 동일한 에이전트가 요구사항·테스트 결과·최종 diff를 대조해 자체 검토한다. 별도 리뷰 에이전트를 실행하지 않는다.

## 리뷰 항목

- 실제 AI 승인과 TEST_MODE, AI 제안과 서버 판정이 혼동되지 않았는가
- `certain`, 전체·매핑별 confidence, 단위 설정, 출처·계층 근거와 반려 결과가 유지되는가
- 본품·사은품, 낱개·포장·전체 수량, 다른 출처의 동치·충돌이 잘못 합쳐지거나 누락되지 않았는가
- LIGHT/FULL 전환 대상·최대 호출 수·통신 오류 처리와 usage·비용 집계가 정확한가
- DTO·Schema·프롬프트·API 문서·화면이 같은 의미와 필드명을 사용하는가
- 인증·키 부재·요청 제한, 로그·보고서의 실제 상품 본문과 인증정보 노출이 없는가
- 운영 평가의 원본 기준값·사람 확정값·현재 실행 결과가 구분되고 백업·복원과 예산 상태가 확인됐는가
- 테스트가 변경을 입증하는가, 실패·건너뜀·미실행을 성공으로 보고하지 않았는가
- 사용자 변경, 생성물, 범위 밖 파일과 배포 권한 경계가 보존됐는가

## 결과

발견 사항은 치명적·높음·중간·낮음의 심각도, 파일·위치, 재현 조건, 영향, 권고와 수정 여부로 기록한다. 발견 사항이 없으면 검토 범위와 남은 한계를 적는다. 기록 여부와 통합 형식은 [보고서 규칙](../report/report-guide.md)을 따른다. 지적을 반영하면 해당 영역을 다시 검증한다.
