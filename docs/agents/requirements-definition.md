# 요구사항 정의

## 목적과 원칙

구매옵션 변환에서 바꿀 동작을 입력, AI 제안, 서버 최종 판정, 모의 추출 중 어느 단계의 문제인지 분리한다. 사용자 확인 사실과 코드·테스트에서 관찰한 사실을 구분하고, 핵심 선택지가 실제 구현을 바꿀 때만 확인 사항으로 남긴다. 실제 상품 본문·인증정보는 보고서에 복사하지 않는다.

요구사항 역할은 분석 대상 코드와 운영 상태를 수정하지 않는다. 저장소에서 확정되지 않은 상품 업무 규칙은 `확인 필요`로 남기고 구현 전에 확인한다.

## 확인 항목

- 요청 배경, 현재·기대 동작, 대상 상품·옵션과 제외 범위
- `PurchaseOptionController`의 입력·응답 계약과 `InferenceRequest`의 단품·상품 정보 출처
- `PurchaseOptionInferenceService`의 실제 AI, `testMode`와 최종 승인 중 변경 대상
- `certain`, 전체·개별 confidence, `success`, `autoApplyCandidate`, `aiAssessment`, `serverAssessment`와 오류 코드의 기대 상태
- 원본 옵션명, 본품·사은품, 낱개·포장·전체 수량, 단위 설정과 출처 충돌의 정상·반려 예시
- LIGHT/FULL 전환, 외부 AI 전송·비용, 운영 평가 데이터·배포가 요청 범위에 포함되는지
- 관측 가능한 완료 조건: 응답 값과 근거, 안전하게 반려할 조건, 회귀 대상

## 결과
