# 구현

## 목적과 원칙

확정된 요구사항과 영향 경로에 맞춰 Java 17 / Spring Boot 모듈의 기존 계약을 최소 범위로 수정한다. 지정 범위 밖의 리팩터링·의존성 변경·전체 포맷팅을 섞지 않고 사용자 변경을 보존한다. 불확실한 업무 규칙은 임의 확정하지 않는다.

## 구현 전후 확인

- 실제 AI, TEST_MODE, `aiAssessment`와 최종 승인 결과를 분리했는가
- `certain`·confidence·구조·단위·근거 검증의 승인 조건과 반려 시 오류 코드·빈 결과 의미가 유지되는가
- 원문 인용, 본품 componentId, 낱개·포장·전체 계층과 명시된 구매옵션 단위 설정이 일치하는가
- 단일 본품 포장당 용량의 좁은 계산 예외를 다른 물리량·여러 본품에 무심코 확대하지 않았는가
- 프롬프트 변경 시 LIGHT/FULL, 사용자 프롬프트, JSON Schema, 파싱·정규화, 버전과 재추론 상한을 함께 검토했는가
- API·화면 변경 시 실제 필드명과 문서·예제·Node 테스트를 맞췄는가
- AI usage·로그 변경 시 호출별 `inferenceId`, 토큰, 비용 미측정 상태와 `elapsedMs`를 보존했는가
- 인증·요청 제한을 검증 편의로 약화하거나 실제 키·상품 본문을 추가하지 않았는가

## 구현 결과 확인

동일한 에이전트가 변경 파일, 핵심 결정과 근거, 수행한 정적 점검, 테스트가 필요한 정상·경계·실패 조건, 미검증 항목을 확인하고 테스트 단계로 이어간다. DB·운영 평가 데이터·외부 AI 호출, commit·push·배포의 권한 경계는 `AGENTS.md`를 따른다. 결과는 [보고서 규칙](../report/report-guide.md)에 따라 기록한다.
