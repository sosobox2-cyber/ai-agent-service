# 구매옵션 프롬프트 평가 기준선과 실패한 개입 기록

2026-10-18 측정. 대상은 `examples/`의 요청 14건이며 모델은 `gpt-4.1-mini`, `temperature=0`이다.
프롬프트는 `coupang-option-v27`에 R9 안내 문구 규칙 2줄을 더한 상태(아래 문서에서 v28로 표기)다.

이 문서의 목적은 두 가지다. 하나는 각 케이스의 실제 정답률을 숫자로 남겨 다음 수정의 기준선으로 쓰는 것이고,
다른 하나는 이미 시도해서 실패한 프롬프트 수정을 기록해 같은 시행착오를 반복하지 않는 것이다.

## 측정 방법과 주의점

`ResultValidator` 통과율은 형식과 제약 위반만 잡는다. **값이 틀렸는데 형식이 맞으면 그대로 통과한다.**
실제로 아래 결함 5건 중 4건은 통과율 100%인 상태에서 발견됐다. 통과율만 보고 프롬프트를 고치면 역주행한다.

`temperature=0`이지만 출력은 결정적이지 않다. 같은 입력이 실행마다 다른 값을 낸다.
**n=1~3 측정으로는 프롬프트 변경 효과와 샘플링 노이즈를 구분할 수 없다.** 아래 수치는 모두 n=10이다.

실제로 n=3에서 `set`과 `weight`가 불안정해 보였으나 n=10에서는 둘 다 정답 고정이었다.
반대로 `cream`은 n=1에서 정상으로 보였으나 n=10에서 70% 오답이었다.

### 도구

| 스크립트 | 용도 |
|---|---|
| `scripts/eval-prompt.ps1` | 요청을 실제 API로 보내고 통과율·자동적용·토큰·비용을 집계해 JSONL로 남긴다 |
| `scripts/compare-eval.ps1` | 두 실행의 케이스별 산출값을 비교해 실행 간 변동을 보여준다 |
| `scripts/summarize-eval.ps1` | 한 실행의 케이스별 값 분포와 빈도를 센다 |

```powershell
# 과금 없이 하네스만 점검
.\scripts\eval-prompt.ps1 -TestMode -Label smoke

# 기준선 측정. 프롬프트 수정 효과를 보려면 -Repeat 10 이상을 권한다
.\scripts\eval-prompt.ps1 -Label baseline -Repeat 10

.\scripts\summarize-eval.ps1 -Label baseline
.\scripts\compare-eval.ps1 -Labels baseline,수정후라벨
```

프롬프트는 `PurchaseOptionPromptProvider` 생성자에서 기동 시 한 번만 읽는다.
프롬프트를 고치면 **반드시 애플리케이션을 재기동해야** 반영된다. 현재 `spring-boot-devtools`는 없다.

호출 비용은 1건당 약 $0.0017이다. 14케이스 × 10회가 약 $0.23이다.

## 기준선 (v28, 각 n=10)

### 안정·정답 9건

`ai`, `rule`, `capacity`, `seafood`, `smartboard`, `toilet-paper`, `set`, `weight`는 10/10 동일한 정답을 낸다.
`uncertain`은 10/10 매핑을 생략하고 `certain=false`로 검토에 회부한다. 이것이 의도된 정상 동작이다.

### 결함 5건

| 케이스 | 오류율 | 내용 | 검증이 잡는가 |
|---|---|---|---|
| `quantity` | 단위 10/10 | 단위가 항상 `매입`이다. 정답은 `개입`. 숫자는 `50`과 `5`가 섞인다 | 아니오 |
| `cream` | 7/10 | 무료체험 50g을 본품에 합산해 `170g`을 낸다. 정답은 `120g` | 아니오 |
| `tv` | 5/10 | `스탠드/벽걸이 구분`이 `이동형스탠드`/`스탠드`/`없음`으로 갈린다 | 아니오 |
| `pillow` | 간헐 | `수량=4개` 대신 `1세트+4매입`으로 오해석하며 중복 매핑을 낸다 | **예** (`DUPLICATE_MAPPING`) |
| `kitchen-towel` | 1/10 | `개당 수량`과 `수량`이 모두 `1개`로 무너진다. 정답은 `140매입`, `12개` | 아니오 |

4건이 `confidence` 0.85~0.9를 달고 자동적용 후보로 올라간다.
**`confidence`는 정확도와 상관이 없다.** `cream`은 70% 틀리면서 0.85~0.9를 유지한다.

`pillow`만 검증에 걸려 검토로 간다. 이 점은 아래 "검증 실패가 항상 나쁜 신호는 아니다"와 연결된다.

## 적용한 수정 (유효)

### R9 안내 문구 규칙

`uncertain` 케이스에서 `productNoticeText`가 `색상: 상세페이지 참조`일 때 모델이 그 문구를 색상 값으로 반환했다.
수정 전 3회 중 2회 발생했고 **자동적용 후보로 승인됐다.** 쿠팡에 "상세페이지 참조"가 색상 옵션으로 올라간다는 뜻이다.

R9 앞에 안내 문구는 값이 아니라는 문단과, 생략이란 항목을 배열에서 빼는 것이지 값을 비우는 것이 아니라는 문단을 추가했다.
수정 후 16/16 정상 생략한다.

두 번째 문단이 필요했던 이유는, 첫 시도에서 모델이 값을 비운 항목을 반환해 `EMPTY_VALUE`와 `INVALID_RESPONSE`가 떴기 때문이다.
판단 자체는 정확했으나 출력 형태가 잘못됐다.

## 실패한 개입 기록

아래 수정은 **시도했다가 측정으로 역효과를 확인하고 되돌렸다.** 다시 시도하지 않는 것을 권한다.

### 1. `quantity`의 단위·숫자 규칙 보강 (2회 실패)

R5와 R10 예시 5에 `50개입`이 정답이라고 **이미 명시되어 있다.** 그런데도 모델은 `5매입`을 낸다.
마지막 시도에서는 모델의 `reason`이 `총 50패치`를 직접 인용하면서도 숫자 `5`를 골랐다.

- 1차: R5 금지 목록에 `5매입` 추가, 예시 5에 "총 N패치의 N이 개당 수량의 숫자"라는 양성 규칙 추가 → **출력 변화 없음**
- 2차: 프롬프트 전체가 `매입`에 편향된 점을 겨냥해 R6의 `N매입` 하드코딩 제거, R5에 "패치는 시트가 아니다" 추가

2차는 **목표 케이스를 더 악화시켰다.** 수정 전 숫자 `50`이 5/10 맞았으나 수정 후 10/10 모두 `5`가 됐다.
`pillow`도 함께 나빠졌다(아래 참조). `set`만 10/10 정답을 유지했다.

### 2. R9 안내 문구 목록에 `없음` 포함

`없음`을 "값이 아닌 문구" 목록에 넣었더니 `pillow`과 `tv`가 `없음`을 **출력값으로** 쓰기 시작했다.
막으려던 실패 모드를 목록이 오히려 유발했다. 현재 목록에서 `없음`과 `-`는 제외했고,
대신 "값이 없다는 뜻의 문자열을 넣은 항목을 반환하지 않는다"로 우회 서술했다.

다만 `tv`는 이 목록과 무관하게도 `없음`을 2/10으로 낸다. 목록이 유일한 원인은 아니다.

### 교훈: 규칙을 더 명확히 쓰는 것은 효과가 없었다

`quantity`와 `cream` 모두 **정답이 프롬프트에 이미 명시되어 있는데도 틀린다.**
`cream`의 "무료 증정분을 합산하지 않는다"는 R10 예시 9에 서술되어 있다.

문구를 추가하면 목표 케이스는 안 바뀌고 다른 케이스가 흔들렸다. 수정 3건 중 유효한 것은 R9 1건뿐이고
나머지 2건은 모두 회귀를 냈다. 이 결함들은 프롬프트 레이어의 문제가 아니라고 본다.

### 교훈: 검증 실패가 항상 나쁜 신호는 아니다

`pillow`은 v28에서 10회 중 4회 `DUPLICATE_MAPPING`으로 걸려 검토에 회부됐다.
실패한 개입 1의 2차 수정 후에는 **40/40 전부 통과했지만** `사이즈=없음`을 6/10으로 내며 자동적용됐다.

통과율만 보면 100%가 60%보다 좋아 보이지만 실제로는 "틀렸지만 잡히는 상태"에서
"틀린 채로 나가는 상태"로 나빠진 것이다. 통과율을 단독 지표로 쓰면 안 되는 이유다.

## 권장 후속 조치

프롬프트 수정으로는 남은 4건을 해결하지 못했다. 코드 레벨의 대응이 필요하다.

1. **`ResultValidator` 교차검증 추가** — 무료 증정·체험분을 본품 중량·수량에 합산했는지,
   `총 N패치` 패턴과 `개당 수량`의 숫자가 일치하는지 확인한다. `cream`과 `quantity`를 겨냥한다.
2. **일치 게이팅** — 같은 요청을 2~3회 호출해 **전부 같은 값일 때만** 자동적용한다.
   다수결은 안 된다. `cream`에 다수결을 쓰면 7:3으로 오답(`170g`)을 확신하게 된다.
   확률적 방어라 완전하지 않다. `cream` 기준 3회 일치를 요구해도 약 37%는 통과한다. 비용은 2~3배다.
3. **모델 상향** — 2026-10-18 기준 검토했으나 진행하지 않기로 결정됐다.
   현재 `gpt-4.1-mini`이고 실패 양상이 "프롬프트에 명시된 규칙을 못 따르는" 형태라 상위 모델에서 해소될 여지가 있으나,
   비용 등의 이유로 선택지에서 제외됐다. 따라서 **실질적인 해결 경로는 위 1번과 2번뿐이다.**
4. **자동적용 임계값 재검토** — 현재 `confidence` 0.8 기준이나,
   측정상 `confidence`와 정확도 사이에 상관이 없다. 임계값 조정으로는 이 결함을 거르지 못한다.
