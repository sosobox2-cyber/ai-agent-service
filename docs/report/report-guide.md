# 단계 보고서 관리

실제로 수행한 요구사항·영향 분석·테스트·교차 검토 결과를 한국어 Markdown으로 남긴다. 메인 에이전트가 직접 수행한 경우도 동일하다. 설명·조회 요청에는 보고서를 만들지 않는다.

- 경로: `docs/report/YYYY-MM-DD/작업제목_단계.md`
- 단계: `요구사항`, `영향분석`, `테스트`, `교차검증`
- 날짜는 작성일의 한국 시간(Asia/Seoul)이다.
- 같은 작업은 같은 제목을 사용하고 공백은 하이픈으로 바꾼다. Windows 금지 문자와 민감정보를 파일명에 넣지 않는다.
- 기존 보고서를 덮어쓰거나 삭제하지 않는다. 중복이면 `_02`, `_03`을 붙인다.
- 상단에 목적·작성일·단계·범위를 적고 코드 근거, 실제 수행 결과, 미검증 항목을 구분한다. 관련 이전 보고서는 상대 링크로 연결한다.
- 수행하지 않은 단계의 빈 보고서를 만들지 않는다. 작은 작업은 각 단계의 결과를 짧게 기록한다.
- 최종 응답에 주요 보고서 링크를 제공한다. 실제 인증정보·상품 본문·AI 응답 원문을 복사하지 않는다.

진행 순서는 [변경 작업 스킬](../../.agents/skills/ai-agent-change-workflow/SKILL.md), 역할별 검토 항목은 [요구사항](../agents/requirements-definition.md), [영향 분석](../agents/impact-analysis.md), [구현](../agents/implementation.md), [테스트](../agents/test-verification.md), [교차 리뷰](../agents/cross-review.md)를 따른다.
