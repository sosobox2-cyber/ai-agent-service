# 단계 보고서 관리

실제로 수행한 요구사항·영향 분석·테스트·교차 검토 결과를 한국어 Markdown으로 남긴다. 메인 에이전트가 직접 수행해도 동일하다. 설명·조회 요청에는 보고서를 만들지 않는다.

## 저장 위치와 이력

- 중간 이상·고위험 변경은 `docs/report/YYYY-MM-DD/작업제목_요구사항.md`, `_영향분석.md`, `_테스트.md`, `_교차검증.md`로 단계를 구분한다. 단계별 파일에는 실제 수행 결과와 이전 단계 링크를 남긴다.
- 작은 변경은 `docs/report/YYYY-MM-DD/작업제목.md` 한 파일에 수행한 단계만 `## 요구사항`, `## 영향분석`, `## 구현`, `## 테스트` 등으로 모은다. 진행 중 위험도가 올라가면 이후부터 단계별 보고서로 전환하고 기존 보고서를 링크한다.
- 날짜는 작성일의 한국 시간(Asia/Seoul)이다. 같은 작업은 같은 제목을 쓰고 공백을 하이픈으로 바꾸며 Windows 금지 문자와 민감정보를 파일명에서 제외한다.
- 기존 보고서는 덮어쓰거나 삭제하지 않는다. 같은 단계의 재검증에는 `_02`, `_03`을 붙이고 이전 결과를 링크한다. 작은 변경의 통합 보고서에서는 기존 절을 지우지 않고 `## 테스트_02`처럼 추가한다. 과거 파일명은 소급 변경하지 않는다.
- 관련 이전 단계·요약 보고서와 근거 문서는 상대 링크로 연결한다. 최종 사용자 응답에는 주요 보고서 링크를 제공한다.

## 내용과 증거

- 상단에 목적, 작성일, 수행한 단계와 검토 범위를 적는다. 현재·기대 동작, 영향 경로, 위험도, 구현 결정과 코드·테스트 근거를 필요한 범위에서 기록한다.
- 테스트에는 **실제 실행 명령**, 통과·실패·건너뜀 수, 외부 AI 호출 여부와 비용·미측정 usage, 환경 때문에 실행하지 못한 항목을 구분한다. 수행하지 않은 단계의 빈 결과를 만들지 않는다.
- 운영 평가에서는 원본 등록 기준값, 사람 확정값, AI 제안, 서버 승인과 비교 결과를 구분한다. 기준 교정으로 오른 일치율을 모델 성능 향상으로 보고하지 않는다.
- 로그·JSONL·백업 ZIP과 실제 요청·응답 본문은 보고서에 복사하지 않는다. 인증정보·상품 식별정보도 결론에 필요한 최소한만 남긴다.
- 교차 검토는 심각도, 근거, 영향, 수정 여부와 남은 위험을 적는다. 같은 에이전트가 수행한 검토는 독립 리뷰라고 표시하지 않는다.

진행 순서는 [변경 작업 스킬](../../.agents/skills/ai-agent-change-workflow/SKILL.md), 역할별 검토 항목은 [요구사항](../agents/requirements-definition.md), [영향 분석](../agents/impact-analysis.md), [구현](../agents/implementation.md), [테스트](../agents/test-verification.md), [교차 리뷰](../agents/cross-review.md)를 따른다.
