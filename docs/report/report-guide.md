# 변경 보고서 규칙

단일 에이전트가 실제 수행한 결과만 한국어로 기록한다. 보고서 작성을 위해 동일한 분석·검증을 반복하지 않는다.

## 작성 여부

- 설명·조회, 문구·링크·포맷 수정, 승인·보안·외부 계약·공통 검증에 영향이 없는 작은 국소 변경은 파일을 만들지 않는다. 최종 답변에 변경 내용, 실행한 검증과 미검증 범위를 남긴다.
- 최종 승인·공통 검증·보안·재추론·실제 AI 전송 변경, 운영 평가·데이터 변경, 또는 사용자가 보고서를 요청한 작업은 보고서를 남긴다. 그 외 변경은 장기 보존할 결정·복잡한 영향·미해결 위험이 있을 때만 작성한다.

## 파일과 내용

- `docs/report/YYYY-MM-DD/작업제목.md` 한 파일에 요구사항·영향·구현 결정·검증·자체 검토를 필요한 만큼 통합한다. 날짜는 한국 시간이며 단계별 별도 파일과 빈 절은 만들지 않는다.
- 실제 실행 명령과 결과, 실패·건너뜀·미실행 및 원인, 남은 위험을 구분한다. AI 호출 시 실제 AI와 TEST_MODE, 비용·미측정 usage를 구분한다.
- 운영 평가에서는 등록 기준값·사람 확정값·AI 제안·서버 승인을 구분하고 기준 교정을 모델 성능 향상으로 보고하지 않는다.
- 자체 검토에서 발견한 문제는 심각도·근거·영향·조치·남은 위험을 기록한다. 독립 리뷰라고 표시하지 않는다.
- 인증정보·실제 상품 본문·로그·JSONL·백업을 복사하지 않는다. 필요한 집계와 파일 위치만 남긴다.
- 기존 보고서는 삭제·덮어쓰기·소급 개명하지 않는다. 같은 작업의 후속 결과는 기존 내용 아래 날짜와 함께 추가한다. 별도 파일이 필요하면 `_02` 등을 붙이고 이전 보고서를 연결한다.
- 최종 답변에는 작성한 보고서만 링크한다. 자세한 절차는 [변경 스킬](../../.agents/skills/ai-agent-change-workflow/SKILL.md)을 따른다.
