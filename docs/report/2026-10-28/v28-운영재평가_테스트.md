# v28 실제 AI 재테스트 — 한 페이지 요약

작성일: 2026-10-28 · 단계: 테스트 · 대상: Railway 운영 v28 · 모델: gpt-4.1-mini-2025-04-14

**오승인 차단은 효과가 있었지만, 구성 충돌과 개당 중량의 합산 오류는 남았다. 지금은 테스트 수를 늘리기보다 본품·포장 계층·출처 충돌을 구분하는 구조를 보완할 단계다.**

| 평가 | 결과 |
|---|---|
| 규모 | 기존 14상품 + 신규 10상품 = **24회 요청, 실제 모델 25회 호출** |
| 기존 오류 4상품 | **4/4 자동 승인 차단**. 단, 중량→개수와 인증번호→모델명 오류는 AI가 여전히 제안했고 서버가 차단 |
| 정상 대조군 7상품 | **7/7 승인 유지, 55개 매핑 값 모두 이전과 동일** |
| 기존 충돌 3상품 | **2상품 여전히 오승인**. 나머지 1상품은 반려됐지만 중량 합산 오류 제안이 남아 충돌 의미 처리가 해결됐다고 볼 수 없음 |
| 신규 10상품 | 8승인·2반려. 주요 값이 타당한 7상품 중 1상품은 계산 연산 표기 오류. **혼합 중량 1상품 오승인**, 상품명 근거 누락·단위 계약 오류 2상품 반려 |
| 비용 | 이번 **$0.053906** · 누적 확인 추정액 **$0.2244144** · 이전 미측정 예약 포함 **$0.3844144** |

## 다음에 고칠 것

1. **출처 충돌 검사:** 상품명 16매/구성 17매, 상품명 4팩/구성 3팩을 동시에 검토하게 해야 한다. 현재는 구성만 보고 승인한다. 출처별 후보와 충돌 여부를 구조화하고 최종 승인 단계에서 확인하는 방향이 우선이다.
2. **개당·포장·전체 수량의 의미 분리:** 160g 15팩 + 200g 3팩에서 개당 중량을 360g으로 합산해 승인했다. 본품별 식별자와 측정 기준(개당/포장/전체)을 구분해 다른 제품의 값을 합치지 않도록 해야 한다. SUM을 일괄 금지하기보다 같은 제품·같은 기준인지 확인해야 한다.
3. **원문 탐색과 응답 계약:** 상품명에 있는 용량·사양을 놓치거나, 화면 73cm 대신 허용되지 않은 29인치를 출력한다. 누락 매핑은 빈 값으로 만들지 말고 생략하며, 최종 값과 계산 출력단위를 일관되게 생성해야 한다.

프롬프트에 금지 문구를 더하는 것만으로 해결됐다고 볼 수 없다. 다음 수정에서는 위 3유형과 정상 7상품을 고정 회귀로 삼고, **오승인 감소와 필요한 값의 추출을 별도로 측정**하는 것이 적절하다. 이 구조 변경은 이번 재평가에서 구현·배포하지 않았다.

## 검증·보존·한계

- FULL 22회, LIGHT 3회. 의류 16단품 사례에서 LIGHT→FULL 재추론 1회. 통신/출력 잘림 오류와 미완료 예약은 없었다.
- 평가 도구 테스트 **9개 통과**. 원본·기존 실행·검토 137파일은 바이트 동일하고 실행 파일만 109→133개로 늘었다. 완료 후 백업 저장.
- 신규 사례는 기존 84상품 밖에서 모델·의류·물티슈·커피·혼합 식품·단일 중량·다층 포장·총수량·길이·화면을 선정했다. 정상값과 오류 판정은 에이전트 검토이며 전체 운영 정답률이 아니다. 사용 인원의 별도 미사용 사례는 확보하지 못했다.
- 혼합 중량의 기존 사례는 v27 반복에서도 반려된 적이 있어 이번 반려를 v28만의 개선으로 귀속할 수 없다. 신규 10상품은 v27 대응 호출이 없어 전후 개선율을 계산하지 않는다.
- 총 $1까지 약 $0.616가 남지만 추가 반복 호출은 멈췄다. 다음 재배포 전에는 평가 이력 보존을 위한 영구 저장소도 필요하다.
