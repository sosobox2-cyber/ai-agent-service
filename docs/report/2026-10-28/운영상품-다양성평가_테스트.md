## 결과와 판단

우선 개선할 문제는 **차원이 다른 숫자를 기본단위로 바꾸는 오승인, 출처·원문 충돌을 놓치는 승인, 구매옵션 의미 정의의 부족**이다. 예시를 계속 추가하기 전에 구매옵션별 의미와 허용 근거를 명확히 하고 평가 기준도 정리해야 한다. 출력이 많은 요청의 분할과 오류 시 usage 보존은 별도 구조 개선 과제다.

현재 프롬프트·애플리케이션을 변경하거나 배포하지 않고 운영 기준 성능을 측정했다. 운영 배포는 ed0aaa6, 로컬 HEAD는 8bb3851이며 Java·프롬프트·설정은 동일하다. 실제 응답 모델은 gpt-4.1-mini-2025-04-14, 프롬프트 버전은 coupang-option-v27이다.

## 표본과 지표의 해석

전체 데이터는 10,270상품·44,898기준 행·구매옵션 68종·조합 81종이다. 숫자만 다른 유사 상품명을 제한하고 새로운 옵션·조합·상품군을 우선했다. 1차는 단품 8개 이하로 선정하고, 후속으로 16단품 및 40단품 경계를 추가했다. 이 표본은 희소 옵션과 오류 발견을 우선하므로 전체 운영 분포의 정답률 추정에 사용하면 안 된다.

시험용·부적합 데이터도 발견했다. c00919, c04747, c04749는 실제 정답 평가에 부적합한 시험용 입력이다. 가스종류의 유일한 사례는 이 중 하나여서 **68종은 옵션명 기준 포괄이며, 68종 모두에 유효한 정답 검증을 완료했다는 뜻은 아니다.** 원문 이미지 링크만 있는 기술서도 존재한다. 이번 텍스트 모델 호출은 이미지 자체를 읽지 않는다.

최소 11건은 평가자가 원문과 현재 계약을 대조해 확인한 사례다. 전체 데이터로 일반화한 오승인율이나 사람의 최종 정답 확정은 아니다. 보강 표본에서는 같은 차원 오류가 1상품 추가 확인됐다. 사람 검토 전 정확한 개선율·정답률을 산출하지 않는다.

코드 근거:

- [FULL 프롬프트 R5](../../../src/main/resources/prompts/coupang-purchase-option-system.txt#L38)는 기본단위 적용 시 숫자 유지 규칙을 가진다. 차원이 다른 숫자 전용까지 허용하는 것으로 모델이 해석한 관측이 있다.
- [FULL 프롬프트 R6](../../../src/main/resources/prompts/coupang-purchase-option-system.txt#L47)는 상품 공통 원문 사용을 단일상품/단품 표시에 결합한다. '없음'이나 다른 단일 옵션 표현의 처리가 불안정하다.
- [ResultValidator](../../../src/main/java/com/cware/ai/inference/ResultValidator.java)는 출력 숫자·단위 및 calculation.outputUnit의 일치를 검사하지만 원문 의미·계산을 재수행하지 않는다. 의미 검증 추가는 별도 요구사항과 승인 경로 회귀 분석이 필요한 변경 후보다.
- [PurchaseOptionInferenceService.infer](../../../src/main/java/com/cware/ai/service/PurchaseOptionInferenceService.java)에서 ai.infer가 예외를 내면 withUsage에 도달하지 못한다. [EvaluationService.run](../../../src/main/java/com/cware/ai/evaluation/EvaluationService.java)은 오류 문자열만 저장하여 response가 null인 실행이 된다.
- [EvaluationService.compare](../../../src/main/java/com/cware/ai/evaluation/EvaluationService.java)는 매핑을 비교하고 [ValueComparison](../../../src/main/java/com/cware/ai/evaluation/ValueComparison.java)은 제한된 표기·물리 단위 동등성만 인정한다. 최종 items의 '없음' 채움과 매핑 누락, 동의어 정책의 구분이 필요하다.

서버에서 원문 숫자를 재계산하는 변경은 이번에 하지 않았다. 다음 구현에서 도입하려면 별도 범위 확정과 기존 승인·재추론·단위·조합 테스트 검토가 필요하다.

표시 변경 실험은 다른 입력을 유지하고 단일 옵션명 '없음'만 '단일상품'으로 바꿨다. 3상품의 변경 요청은 2건 승인, 원본 최초·재실행은 모두 보류였다. 하지만 c07126은 매핑 내용이 같고 승인 여부만 달라졌다. **표시 치환만으로 정확성이 개선됐다고 결론내릴 수 없으며 일괄 적용도 하지 않았다.** 모든 변경 요청 다음에 원본 요청을 재실행해 운영 화면 최신 결과는 원본 입력 기준으로 남겼다.

명확한 색상/사이즈 단품은 5단품 10행과 16단품 32행이 모두 일치했다. 40단품 80매핑이 필요한 신발(FULL)과 의류(LIGHT)는 모두 AI_OUTPUT_TRUNCATED가 발생했다. 단순히 모델 출력 한도를 올리기보다 단품 보존·최종 조합 중복 검사·비용 상한을 포함한 분할 설계를 권한다. 출력 잘림 2건을 값 정확도 평가의 160개 독립 오답처럼 해석하지 않는다.

## 운영 이력과 검증

실행 전후 ZIP 백업을 비교했다. 원본 metadata/cases 및 기존 reviews/review-history 총 28개 파일의 해시가 모두 같고 새 검토 파일은 0개, 새 실행 파일은 정확히 95개다. 원본과 사람의 검토를 변경하지 않았다. 기존 성공 확인은 과거 실행에 연결된 채 보존되며 새 실행을 자동 성공 확인하지 않는다.

운영 데이터셋의 현재 테스트된 상품은 89개다. 기존 11개와 이번 84개 중 겹치는 6개를 제외한 수다. 새 실행은 운영 화면에서 조회할 수 있다. 검토 메모는 자동 승인 검토가 영구 운영 데이터 변경에 대한 명시적 승인이 필요하다고 거절하여 **저장하지 않았다**. 저장 후보는 [교차검증 및 검토 메모 초안](운영상품-다양성평가_교차검증.md)에 있다.
