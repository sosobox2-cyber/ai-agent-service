# 계산 단위와 수량 표기 동치 v36

작성일: 2026-10-28 · 범위: 실제 AI 승인 전 단위 검증 · 위험도: 높음

## 요구사항

v35 운영 평가 11건에서 정상 종이 상품의 `37m` 값과 계산 출력 `cm` 불일치, 물티슈 `70매` 원문과 허용 출력 `70매입`의 표기 차이로 정확한 제안 2건이 반려됐다. 원문이 없는 `1개` 추정과 충돌·혼합 구성은 계속 반려한다.

## 영향분석과 구현

`DIRECT` 계산의 단일 물리 피연산자, 출력값, 허용 단위가 정확히 일치하고 계산 출력 단위만 기본 단위로 잘못 쓰인 경우 계산 출력 단위를 피연산자 단위로 맞춘다. 원문 `매`와 허용 출력 `매입`의 동일 수량 표기만 개수 단위 선호 검사에서 허용한다. 수치, 원문 인용, 피연산자, 신뢰도, 출처 충돌 및 계층 검사는 유지한다. 다른 개수 단위 변경은 반려한다.

## 테스트

관련 Java 테스트 36개 통과. 전체 Java 빌드 301개 중 300개 통과, 유료 호출 테스트 1개 제외. Node 13개 통과. v35 운영 데이터셋 2개를 배포 전 백업했다. 처음에는 자동 승인 검토가 명시적 커밋 지시 부재로 거절했으나, 사용자가 v36 커밋·푸시·운영 배포를 명시적으로 승인했다.

운영 커밋 `9552857`의 Railway 배포 `11f30a0e-0133-4ed7-b1aa-4734659f4475`는 성공했다. 무과금 모의 호출은 `promptVersion=coupang-option-v36`, `TEST_MODE`, `success=false`를 확인했다. 배포 후 데이터셋 2개를 복원하고 백업과 비교했다. 주 데이터셋 317개 파일, 보조 데이터셋 1개 파일 모두 변경·추가 0개였다.

실제 AI 운영 재시험 9건: 정상 대조 4건(`c00041`, `c01623`, `c00803`, `c00005`)이 모두 승인되고 등록 기준 옵션 10개가 정확히 일치했다. 출처 충돌 2건과 혼합 구성 1건은 모두 `REVIEW_REQUIRED`로 반려됐다. 원문에 없는 `1개`를 추정한 정상 상품 2건도 `QUANTITY_BINDING_REQUIRED` 등으로 반려됐다. 누적 예산 원장 집계는 **$0.5796264**(미측정 2건의 예약 $0.16 포함), 미완료 예약은 0건이다. 이번 9건의 사용량 기반 비용 추정 합계는 약 **$0.0286**이다. 재시험 후 활성 데이터셋도 별도 백업했다.

## 교차검증과 한계

상품 20161757의 원문 `50ml×30포×4세트`는 판매 수량을 박스·세트로 잡으면 포장 하나당 30포 × 50ml = 1500ml, 낱개 포로 잡으면 총 120개에 개당 50ml다. 사용자가 이 기준을 확인했다. 따라서 운영에서 승인된 `4세트 + 개당 용량 50ml`는 판매 수량과 개당 용량의 계층이 다른 오승인 사례다. 현재 프롬프트는 개당 용량을 내용물 한 개 기준으로 설명하고, 서버 검증은 두 매핑의 기준 계층을 대조하지 않아 통과한다. 이 결함은 v36에서 해결되지 않았다. 자동 승인 차단과 올바른 포장당 용량 산출을 위해서는 계산 연산·근거 연결·계층 검증의 별도 변경과 회귀 평가가 필요하다. 원문에 없는 `1개` 반려 두 건은 승인 기준을 완화하지 않는다. 현재 9건은 회귀 표본이며 전체 운영 정확도의 추정치는 아니다.
