# 수량 출처·계층 검증 교차 검토

작성일: 2026-10-28 · 단계: 교차검증 · 수행: 동일 에이전트 자체 검토, 독립 검토 아님

## 발견 사항과 조치

| 중요도 | 발견·근거 | 조치 |
|---|---|---|
| 높음 | 기존 FULL 예시 7이 이종 김치 중량 합계를 개당 중량으로 제출하도록 지시해 새 규칙과 충돌 | 이종 MAIN 사실을 보존하고 해당 매핑을 생략·보류하는 예시로 교체 |
| 높음 | 매핑에서 충돌 항목을 빼면 매핑별 검사만으로는 충돌을 놓침 | 원문 사실을 루트 목록으로 분리하고 전체 사실 충돌 검사 후 바인딩 검증 |
| 높음 | 원문 70ml를 COUNT/개로 선언하면 단위 필드 검사만으로 우회 가능 | 실제 숫자 뒤 물리 단위 확인 및 위장 입력 회귀 추가 |
| 높음 | 같은 본품 사실을 출처만 달리해 중복 합산하거나 동일 피연산자를 반복 사용 가능 | 근거 중복·동일 관측·피연산자 중복 검사 추가 |
| 중간 | 숫자 없는 세트 근거로 명시된 판매 세트 수를 무시할 수 있음 | 명시 숫자+세트에 null amount 금지, 암묵적 1세트도 출처 충돌 비교에 포함 |
| 중간 | 초기 DTO 확장 후 정규화·검토 전환에서 근거 유실 위험 | CountUnitNormalizer, PurchaseOptionAiService.review, AiAssessment 전달 및 통합 테스트 확인 |
| 중간 | 기존 테스트가 원문과 맞지 않는 출처 또는 근거 없는 응답 승인에 의존 | 해당 기대를 반려·제안 보존으로 변경. 정상 대역은 새 계약에 맞게 명시 근거 추가 |
| 낮음 | 초기 컴파일에서 제네릭 List 타입 추론 불일치 | 명시 타입으로 수정 후 전체 컴파일·회귀 통과 |

## 경계 확인

- 실제 경로는 ResultValidator.validateAiProposal에서 새 검증을 사용하고 모의 추출은 validateProposal을 사용한다. 모의 중량 합산 도우미를 실제 AI 승인에 연결하지 않았다.
- 스키마 확장은 FULL+대상 4옵션에만 적용한다. 기존 의류 FULL/LIGHT snapshot 테스트가 통과한다. 사용자 프롬프트는 스키마에 해당 필드가 있을 때만 출처·계층을 요청한다.
- 신뢰도·최종 빈 결과·기존 오류 코드와 최대 1회 FULL 전환을 유지한다. SOURCE_CONFLICT 등의 구체 사유는 validationErrors에 기록한다.
- 과거 응답은 새 필드 없이 역직렬화된다. 단, 과거 수량 제안을 새로운 승인 경로에 다시 넣으면 필수 근거 부재로 반려한다. 이는 의도한 버전 경계이며 과거 저장 이력을 수정하지 않는다.
- 기본 단위를 임의로 추가하지 않는다. 물리 단위의 동치 비교와 단일 사실의 값 확인만 수행하며 일반 SUM 산술은 재계산하지 않는다.
- MAIN/EXTRA 및 계층의 의미 판별, 미추출 근거 누락은 여전히 AI의 한계다. 사은품 표기가 있는 인용을 요구하지만 해당 표기가 정확히 어떤 구성품에 대응하는지까지 완전하게 해석하지 않는다.
- quote는 공백 정규화 후 원문 포함 여부를 검사한다. 기존 evidenceText는 요약 필드라 엄격한 인용 검증 대상이 아니며 새 facts.quote와 구분하여 문서화했다.
- 코드·문서·테스트에 새 실제 상품 원문이나 비밀 값을 추가하지 않았다. 기존 로컬 운영 자료를 사용하는 검증은 명시적 시스템 속성으로만 실행한다.
- 사용자 IDE 설정·이전 평가 도구 수정·보고서는 유지했고 운영 데이터·설정·서비스를 변경하지 않았다.

## 남은 검증

실제 모델의 새 스키마 생성 성공률, 출력 토큰 증가, 정상 상품의 검토 전환율은 운영 또는 별도 검증 환경에서 소표본 호출로 확인해야 한다. 55개 값 유지 검증은 기존 근거에 계층을 부여한 대역 검증이며 실제 AI 개선율로 보고하지 않는다.
