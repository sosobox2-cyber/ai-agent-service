## 요구사항과 영향 분석

기간 숫자를 COUNT 사실·수량 피연산자로 승인하는 경로와, 색상 값에 명백한 비색상을 승인하는 경로를 서버 검증으로 차단한다. 프롬프트·Schema는 수정하지 않으며 버전만 `coupang-option-v43`으로 올린다. 기존 미커밋 도구·재채점 보고서 5개는 Node 27개 통과 후 `c2c8460`으로 먼저 커밋했다. `.run`, `.claude`, 백업 파일은 보존하고 커밋하지 않았다.

위험도는 **높음**이다. `PurchaseOptionInferenceService.infer → 정규화 → assess → ResultValidator.validateAiProposal → AiValueContract / QuantityEvidenceValidator`의 실제 AI 승인에 영향을 준다. 같은 검증은 `PurchaseOptionAiService → AiInferenceValidator`에도 적용되므로 새로 검증 실패한 LIGHT 응답은 기존 정책에 따라 FULL 한 번의 대상이 될 수 있다. 재추론 상한·통신 오류 처리·신뢰도 조건은 변경하지 않았다. 실제 호출 시 추가 비용 가능성은 기존 LIGHT 재추론 범위 안에 있다. 모의 `validateProposal` 경로에는 새 의미 검사를 적용하지 않는다.

실패 시 `RESULT_VALIDATION_FAILED`, `success=false`, `autoApplyCandidate=false`, 빈 매핑·items와 `aiAssessment` 보존을 유지한다. 검증은 대역·고정 테스트 및 로컬 저장 응답 재생으로만 수행한다. 정상 개수, 기간과 개수 혼재, 사용하지 않은 기간 사실, 색상 이름의 슬래시, 색상 이외의 FREE, 기존 승인·보안·재추론 전체 회귀를 확인한다.

## 원인 특정과 수정 전 재현

원장 이벤트의 `id.json`이 로컬 저장 파일이다. 운영 `runId.json`으로 읽으면 파일이 없으므로 실제 로컬 저장 방식에 맞췄다. 계획의 trialId로 completed 이벤트를 고르고 최신 이벤트를 적용했다. 150개 중 AI 제안이 있는 저장 응답은 149개다.

| 사례 | COUNT facts | 수량 calculation | 원문 기간 |
| --- | --- | --- | --- |
| c01237 | amount=36, unit=개, quote=36개, PACK·TOTAL 각 1개 | DIRECT, 36개, productNoticeText의 36개 | 개봉 전·후 36개월 |
| c03164 | amount=36, unit=개, quote=36개, TOTAL | DIRECT, 36개, productNoticeText의 36개 | 사용기한 36개월 |
| c01818 | amount=24, unit=개, quote=24개, TOTAL | DIRECT, 24개, productNoticeText의 24개 | 제조일로부터 24개월 |
| c04944 | amount=12, unit=개, quote=12개, TOTAL | DIRECT, 12개, productNoticeText의 12개 | 소비기한 12개월 |

모두 role=MAIN이며 계산 operand의 amount/unit/evidence도 해당 TOTAL 사실과 일치했다. 기존 코드가 통과시킨 이유는 다음과 같다.

1. `QuantityEvidenceValidator.validate`의 정규화 문자열 `contains` 대조는 `36개월` 안의 `36개`를 허용한다.
2. `quotedNumber`는 COUNT의 숫자 뒤에 단위를 요구하지 않으며, 물리량 접미사만 배제했다. 잘린 인용문의 `36`은 통과한다.
3. `canonical`은 원문 단위가 아니라 AI가 선언한 unit=개가 COUNTS 집합에 있는지 검사하므로 36으로 정규화한다.
4. `deriveBindings`는 TOTAL 사실과 DIRECT 피연산자의 출처·숫자·단위·인용문 일치를 확인한다. 서로 같은 잘린 인용문이라 통과한다. `validateBinding`도 출력 숫자와 canonical이 같아 통과한다.
5. `ResultValidator`의 구조·단위 검사는 36개 등을 허용하고, 다른 출처의 포장 수 검사도 이 기간 오류를 검사하지 않는다. certain=true와 최저 confidence 0.90이므로 서비스가 승인한다.

수정 전에 `QuantityEvidenceTest#reproducesTruncatedDurationQuoteApproval`에서 36·24·12의 잘린 인용문을 그대로 구성해 success=true를 확인했다. 같은 실행의 `V43StoredProposalReplayTest`는 **실제 저장된 4개 입력·제안 모두 승인**을 단언했다. 두 테스트 통과, 149건 재생의 원래 승인/재생 승인 모두 68건이며 불일치 0이었다. 기록은 `target/v43-baseline-test.log`, `target/v42-baseline-replay.json`이다. 수정 후 단위 테스트는 반려를 기대하도록 바꿨다.

색상 c00871의 FREE는 confidence=0.80, c09710의 없음은 0.90이며 둘 다 certain=true였다. 기존 `AiValueContract`는 사용 인원·인증번호·물리량 변환만 검사했고 색상 의미 검사가 없었다. 구조 및 신뢰도 기준을 충족해 승인됐다.

## 구현 결정

### 기간 숫자 배제

`QuantityEvidenceValidator.countQuoteInSource`가 제출된 인용문이 원문에 나타나는 위치를 찾고, **그 위치의 숫자 바로 뒤**를 검사한다. 다른 원문 숫자를 추출하거나 수량을 재계산하지 않는다. 개월·월·년·일·주·시간·분·초와 기존 물리량 단위를 COUNT로 인정하지 않는다. 공백이 있어도 같은 방식으로 판단하고, 숫자 일부를 인용하는 우회도 배제한다. COUNT 피연산자도 자체 인용 출처로 검사한다.

`3개월분`, `30일분`은 복용·사용 기간일 뿐 개수를 증명하지 않으므로 해당 숫자를 배제한다. `3개월분 30개입`의 30개는 독립된 명시 개수이므로 유지한다. 기간 사실은 유효한 canonical 값에 등록하지 않고, 해당 사실을 매핑에 연결하거나 기간 숫자를 피연산자로 사용할 때 반려한다.

초기 구현은 사용하지 않은 기간 사실도 상품 전체 오류로 만들었다. 재생에서 기존 정답 승인 c02023이 반려로 바뀌었다. 이 제안은 상품명의 6개월분을 6개 사실로도 적었으나, 실제 수량 매핑은 구성의 독립된 6박스를 사용한다. 따라서 기간 사실은 값으로 인정하지 않되 사용하지 않았다면 전체 반려하지 않도록 좁혔다. `unusedDurationFactDoesNotInvalidateIndependentPackagingCount`로 일반화한 회귀 테스트를 추가했고 새 오반려가 사라졌다. caseId에 따른 운영 특례는 없다.

### 색상 값 최소 검증

기존 모의 대상명 규칙(색상·컬러 포함 또는 COLOR)을 확인한 뒤 실제 AI 계약에 같은 계열을 적용했다. 영문 color는 대소문자를 구분하지 않는다. 따라서 색상/향과 4도어 위치별 색상도 대상이다.

- FREE/F/프리, 없음/해당없음/-, S/M/L/XL 계열, 숫자 사이즈와 mm/cm/호/인치, 사이즈만의 슬래시·범위 표기를 반려한다.
- 쉼표·전각 쉼표·열거 쉼표·세미콜론·세로줄·더하기·앤드·가운뎃점·줄바꿈은 명확한 목록 구분자로 반려한다.
- `/`는 모든 조각이 알려진 기본 색 이름일 때만 목록으로 본다. 블랙/화이트는 반려하고 네온/옐로우는 유지한다. 자유로운 색상 사전을 만들거나 모든 슬래시를 막지 않는다.
- 단일 색 이름, 향을 겸한 대상의 단일 향 이름, 색상 이외 대상의 FREE는 유지한다. 오류는 `COLOR_VALUE_INVALID`로 식별한다.

프롬프트·JSON Schema 수정은 필요하지 않다고 판단했다. `application.yml`의 promptVersion, `eval-diverse.cjs` 허용 목록을 v43으로 갱신하고 미검증 버전 예시는 v44로 이동했다. Node 테스트에서 v43 실행 설정을 대역으로 검증한다. `ai-operations.md`, `api-reference.md`에 변경을 적었다.

## 별도 관점 diff 검토와 미검증 범위

최종 승인, 출처의 숫자 경계, SUM·PACK_CAPACITY 연결, 빈 결과·제안 보존, 실제 AI/모의 경로, 재추론, 버전 허용, 비밀정보·대상 밖 파일을 같은 에이전트가 다시 점검했다. 사용하지 않은 기간 사실을 제외하는 수정으로 독립된 포장 근거를 유지한다. 색상 슬래시는 보수적으로 알려진 기본 색만 판정하므로 모르는 색 이름의 목록까지 포괄하지 않는다.

실제 AI의 새 생성, LIGHT→FULL 실제 호출 품질·비용, 운영 서버·HTTP·배포는 미검증이다. 저장 응답에 AI 제안이 없는 1건은 재생 대상 밖이다. 확정값 없는 상품, 남은 오승인 2건, 애매한 색 이름 목록·단품별 배정의 정당성은 보장하지 않는다. 이번 결과는 저장 제안에 대한 검증 효과이며 새 모델 생성 정확도의 측정이 아니다.
