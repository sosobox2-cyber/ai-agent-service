# v31 근거 구조 단순화와 운영 검증

작성일: 2026-10-28 · 위험도: 높음(실제 AI 출력 스키마와 최종 승인 검증)

## 요구사항과 영향

v30 실제 평가에서 정상 7상품 중 3상품이 반려됐다. 별도 `bindings` 목록의 중복, 길이를 용량 사실로 잘못 기록한 오류, 사실·피연산자의 출처 불일치가 주요 원인이다. 혼합 본품 중량과 출처 충돌 오승인은 계속 차단해야 한다. 대상은 FULL의 4개 수량 계열 옵션이며 LIGHT, 모의 추출, 다른 옵션의 계약은 유지한다.

## 변경

- AI의 `quantityEvidence`를 `facts`와 `sourceReviews`로 줄였다. 서버는 각 수량 매핑의 기존 계산 피연산자를 원문 사실과 정확히 대조해 연결한다. 같은 피연산자에 여러 사실이 맞으면 임의로 고르지 않고 검토로 보낸다. 과거 이력의 `bindings`도 기존 검증 경로로 읽는다.
- 사실 스키마에서 COUNT는 PACK/TOTAL과 개수 단위, WEIGHT·VOLUME은 ITEM과 물리 단위만 허용한다. 길이 m/cm 사실을 용량으로 제출하는 경로를 막는다.
- 단일 단품의 상품명과 구성에 서로 다른 팩·롤·매수가 명시되면 AI가 한쪽 사실을 빠뜨려도 서버가 충돌을 검사한다. `16x6`과 `17매 6팩`은 뒤쪽 포장 수가 같을 때 포장당 매수 충돌로 본다.
- 프롬프트와 API·운영 문서를 v31 계약에 맞췄다. 검토 결과의 원문 사실과 계산 정보는 보존한다.

## 검증 기준과 제한

로컬 대역의 원문 인용·서버 연결·모호한 연결·서로 다른 출처 충돌, 전체 Java 및 화면·예산 Node 테스트를 확인한다. 기존 v30 실제 응답 24건을 새 연결 방식으로 오프라인 재판정한다. 오프라인 이력의 `certain=false`는 당시 반려 결과이므로 검증 오류가 사라져도 실제 승인 회복으로 세지 않는다. 재배포 후 정상 7상품/55값, 추가 정상 2상품, 충돌 2상품과 혼합 중량 1상품을 운영에서 소규모 재검증한다.

서버의 직접 충돌 검사는 명시된 팩·롤·매수와 위 `N x M` 형식에 한정된다. 다른 본품·속성의 모든 숫자 추출을 대신하지 않는다. 정확한 AI 생성 품질과 정상 승인 회복은 운영 재검증 결과로 판정한다.

## v31 운영 결과와 자체 교차 검토

배포 `1a2ade4` 성공, 두 데이터셋의 백업·복원 내용 동일. 실제 AI 11건을 재비교했다. 정상 8건 중 자동 승인 3건(c00084, c00005, c00066)이지만 c00005의 `2박스·30정`이 `2개·30개`로 바뀐 잘못된 승인이므로 품질상 정상 승인은 2건이다. c00611·c00168 출처 충돌과 c00040 혼합 구성은 반려됐다. 추가 비용 추정 $0.0324544, 누적 예약 포함 $0.5003064.

교차 검토에서 서로 다른 COUNT 단위인 70매와 10팩을 같은 계층으로 AI가 잘못 표시하면 서버도 숫자만 비교해 가짜 충돌을 만들 수 있음을 확인했다. 설정된 단위 선택지에 박스·정이 있는데 AI가 기본 개로 바꾼 제안이 승인되는 문제도 발견했다. v32에서는 두 오류를 서버에서 수정한다. 나머지 정상 반려는 AI의 잘못된 사실·계층 분류 또는 출처 검토 불일치가 원인이어서 이 변경만으로 모두 회복되지는 않는다.
