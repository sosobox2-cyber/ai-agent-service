# 운영상품 다양성 평가 — 교차검증 및 검토 메모 초안

- 목적: 실행 결과·보고서·운영 변경 범위를 대조하고 저장할 검토 내용을 제시한다.
- 작성일: 2026-10-28
- 단계: 교차검증
- 범위: 표본 계획, 실제 실행 원장, 원본/검토 보존, 평가 도구와 보고서.
- 선행: [테스트 결과와 개선 우선순위](운영상품-다양성평가_테스트.md)

메인 에이전트가 직접 검토했다. 독립 리뷰나 사람의 정답 확정으로 표시하지 않는다.

## 확인 결과

- 실제 AI와 모의를 분리했다. 95건 모두 운영 평가 API의 AI 모드이며 대역 테스트 8개는 도구 제어 검증이다.
- 응답으로 확인되는 모델 호출 96회와 usage가 누락된 출력 잘림 2건을 구분했다. 비용 미상을 0으로 계산하지 않고 예약금 USD 0.16을 유지했다.
- 승인율과 기준값 일치율을 분리했다. 반려 제안도 비교하는 기존 동작과 정답 기준 오류를 보고서에 명시했다.
- 대조 실험 입력과 원본 입력을 실행 이력에 남겼고 마지막에는 원본을 재실행했다.
- 백업의 원본/기존 검토 파일 28개가 동일하고 새 실행만 95개 추가됐다.
- 애플리케이션·프롬프트·설정·최종 승인 규칙·재추론 규칙을 수정하지 않았다. 커밋·푸시·배포하지 않았다.
- 사용자 작업 파일 .run/AI Agent Service.run.xml, .claude/settings.json, README.md~, pom.xml~은 보존했다.
- 비용 도구는 v27/gpt-4.1-mini/출력 4096/최대 2호출 조건 전용이다. 모델이나 한도가 바뀌면 예약금 가정을 먼저 재검토해야 한다.
- 예산 원장은 이 평가 작업의 요청만 집계한다. 같은 공급자 계정의 다른 사용자가 별도로 쓴 비용을 포함하지 않는다.

## 발견과 후속 조치

| 심각도 | 발견 | 상태 |
|---|---|---|
| 높음 | 차원이 다른 숫자 전용 및 근거 없는 속성을 승인 | 실제 재현, 개선 후보 도출; 운영 코드 미수정 |
| 높음 | 원문 충돌 및 혼합 구성 대표값 승인 | 원문/응답 대조, 변경 범위 별도 설계 필요 |
| 중간 | 출력 오류 시 호출 usage가 평가 응답에서 사라짐 | 40단품 2건 재현, 예약금으로 예산 보존 |
| 중간 | 데이터 기준 오류가 AI 오답으로 집계됨 | 기준 검토 초안 준비, 확정값 미변경 |
| 중간 | 같은 매핑 또는 같은 입력의 승인 여부가 달라짐 | 대조/재실행 확인, 표본 확대 없이 개선율 단정 금지 |
| 낮음 | 기존 예제 평가 도구의 비용 누락값 처리·예산 통제 부족 | 이번 전용 도구에 예약·중단·원장·잠금 적용, 대역 검증 통과 |

## 운영 저장을 위한 검토 메모 초안

대상은 **30상품·57기준 행**이다. 아래 내용은 아직 운영에 저장되지 않았다. 실행 시 기존 검토가 있는 행은 건너뛰고 확정값을 바꾸지 않는다. 새 메모에는 'AI 자동 검토 · 사람 확정 아님'과 최초 관측 실행 ID를 붙이며 SUCCESS를 설정하지 않는다. 기준값 검토는 REFERENCE_ISSUE, 나머지는 NEEDS_FIX로 기록할 계획이다.

자동 승인 검토는 이 메모 일괄 저장을 거절했다. 사유는 테스트·분석은 승인됐지만 영구 운영 검토 데이터 추가에 대한 명시적 승인이 없다는 것이다. 메모 저장 스크립트는 실행되지 않았고 백업 대조에서도 검토 변경이 0개임을 확인했다. 사용자 승인 후에만 저장할 수 있다.
