# 검토 화면·평가 도구 운영 배포

- 작성일: 2026-10-28 (Asia/Seoul)
- 목적: 승인된 미커밋 변경만 커밋하고 Railway 운영에 배포하며 평가 데이터와 검토 이력을 보존한다.
- 단계: 요구사항·영향 분석 → 변경 검토 → 필수 검증 → 커밋·배포 → 무과금 확인·보존 대조
- 근거: [검토 지원·수량 근거 분석](gold150-검토지원과-수량근거-분석_단계.md), [v42 운영 평가](gold150-v42-운영평가_단계.md)
- 실제 OpenAI 호출·추가 AI 비용: 0건·$0. 실제 AI 정확성 평가는 수행하지 않는다.

## 요구사항과 영향 분석

`AGENTS.md`와 [변경 작업 스킬](../../../.agents/skills/ai-agent-change-workflow/SKILL.md)을 먼저 읽었다. 사용자 지정 11개 파일만 새 코드·보고서 커밋 대상으로 확인했다. `.run/AI Agent Service.run.xml`, `.claude/settings.json`, `README.md~`, `pom.xml~`는 명시적 제외 파일로 보존했다. 이외 범위 밖 작업 트리 변경은 없었다.

예산은 새 계획에 $2를 사용하고 기존 $0.95·$1.45 계획의 차단값은 유지한다. 비용 예약·중복 trial 방지는 유지한다. 기준값 의심 집계는 공식 일치 판정을 바꾸지 않는다. 화면은 dataset·case·row로 상세·강조·검토 입력을 열고, 정렬 도구는 로컬 CSV의 순서·링크를 만든다. 추론 서비스·프롬프트·Schema·보안 설정은 변경 대상이 아니며 버전은 v42 그대로다.

운영 배포는 영구 볼륨 없는 기존 서비스의 데이터셋 초기화 위험이 있다. 기존 절차대로 배포 전에 두 데이터셋을 백업하고, 필요 시 공식 백업 가져오기 API로 복원한다. 검토·확정값을 새로 쓰지 않고 기존 이력을 보존하는 범위다. 배포에 필요한 저장소 푸시와 복원은 사용자 명시 승인 범위다.

## 배포 결과와 복원

Railway `railway_list_deployments`와 `railway_get_status`로 배포 **SUCCESS**를 확인했다. 생성 시각은 2026-10-28 17:35:25 KST, 성공 시각은 17:36:46 KST다. 배포 ID `b0fc55bd-8d20-4df2-9a84-1c3c7ef87b44`, 커밋 `ae7de89fe806e4a6077b0d15e5b2b6d5c09e3f42`이며 미적용 변경이나 추가 배포는 없다.

배포 후 평가 데이터셋 목록이 0개임을 확인했다. 각 ZIP의 기존 가져오기 API(`/imports` → `/imports/{id}/parts/{part}` → `/imports/{id}/complete`)로 백업을 복원하고 ZIP을 다시 내려받았다. 기존 검토 기록을 복구한 것이며 review API로 정답·메모를 새로 쓰지 않았다.

| 주 평가셋 | `74df8638-d622-498b-a242-f894e581c2e2` | **`634fbef8-6b41-4ce8-a170-8b635259592e`** | 10,270 | 252 | 3 |

sourceHash 전체와 상품 수·집계 상태를 배포 전후 대조해 동일함을 확인했다. 주 평가셋의 MATCH 37, MISMATCH 77, REVIEW_REQUIRED 133, ERROR 3, REGRESSION 1 등 나머지 집계도 모두 일치한다.

PowerShell `ZipFile.OpenRead`로 ZIP의 모든 항목을 읽었다. metadata.json은 새 ID·importedAt만 제외하고 비교했고, 나머지는 SHA-256으로 비교했다. 검토 이력은 파일명이 재생성될 수 있어 내용 해시를 정렬하고 중복 개수까지 비교했다. 비교 대상은 주 평가셋 653개·보조 평가셋 5개로 합계 **658개 파일, 변경·추가 0개**다. 주 평가셋의 검토 이력 파일 19개도 내용·개수가 유지됐다.

첫 로컬 비교 보조 명령에서 PowerShell 속성 컬렉션의 Count 처리로 항목 수 불일치 오류가 났다. 실제 ZIP의 항목 이름과 개수를 확인하니 전후 동일했다. 컬렉션을 배열로 명시해 다시 비교한 결과 전체 내용이 일치했다. 이는 검증 보조 명령의 오류이며 운영 데이터 손실이나 필수 테스트 실패는 아니었다. 오류 실행을 검증 성공으로 간주하지 않았다.

증거는 Git 제외 배포 폴더의 `restored.json`, `restore-journal.jsonl`, 복원 전후 ZIP, `preservation.json`, `final-checks.json`에 저장했다. 제외 파일 4개와 예산 원장 1개의 SHA-256이 최종 상태에서도 모두 일치한다. 코드 커밋 3개의 변경 파일은 사용자 허용 11개와 일치하며 로그·IDE 설정·백업 파일은 포함하지 않았다.

## 교차 검토와 완료 범위

메인 에이전트가 최종 diff·커밋 파일 목록·필수 테스트·운영 정적 파일·원장 해시·복원 집계를 대조했다. 독립 리뷰는 아니다. 서버 추론 경로·프롬프트 버전·인증·요청 제한 변경은 없으며 실제 OpenAI 호출, `eval-diverse.cjs run`, review 쓰기, 예산 원장 변경도 하지 않았다.

배포 결과 보고서는 별도 한국어 로컬 커밋으로 저장한다. 기존 배포 절차와 같이 이 사후 보고서 커밋은 추가 푸시하지 않아, 보고서만을 위한 자동 재배포·평가셋 재초기화를 피한다. 배포된 소스 커밋은 위 `ae7de89`이며 사후 보고서 커밋은 이와 별개다.

남은 미검증 범위는 브라우저의 실제 화면 동작과 실제 AI의 생성 품질이다. 전자는 사용자 허용 대체 검증인 정적 코드 대조까지 수행했고, 후자는 이번 요청의 금지 범위여서 수행하지 않았다.

## 최종 상태 점검에서 발견한 병행 변경

사후 보고서 커밋 `a7c1a6d` 직후 최종 `git status --short`에서 `scripts/review-queue.cjs`에 새 미커밋 변경을 발견했다. 내용은 `.txt` 출력 경로에 UTF-16LE 탭 구분 텍스트를 쓰는 구형 Excel 호환 기능 6줄이다. 최초 확인·필수 검증·코드 커밋 때의 내용에는 없었고 이 배포 작업에서는 해당 코드를 수정하지 않았다. 병행 작업으로 보이는 이 변경은 보존하고 이번 커밋·운영 배포에는 포함하지 않았다. 따라서 현재 작업 트리에 명시적 제외 파일 외에 이 추가 미커밋 변경이 남아 있다. 배포된 검토 화면·기존 CSV 출력과 새 ID 링크의 검증 결과는 위와 같다.
