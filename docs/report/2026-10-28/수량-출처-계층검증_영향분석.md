# 수량 출처·계층 검증 영향 분석

작성일: 2026-10-28 · 단계: 영향분석 · 위험도: 높음(최종 승인·FULL 스키마·출처 대조 변경)

MappingProposal에 quantityEvidence를 추가하고 실제 AI 재추론 판단과 최종 승인에서 동일 검증기를 사용한다. 정규화·검토 전환 시 근거를 보존하고 AiAssessment에도 전달한다. 기존 생성자와 null 필드의 JSON 생략을 유지하여 과거 이력 및 비대상 LIGHT의 응답 구조를 보존한다.

스키마는 FULL이면서 대상 4옵션을 요청할 때만 확장한다. LIGHT 및 수량 대상 없는 FULL 스키마는 그대로다. 프롬프트는 v29로 변경하며 사용자 프롬프트·파싱·버전·기존 snapshot 테스트를 함께 확인한다. 새 필드에 대한 과거 DTO의 엄격 역직렬화 클라이언트는 업데이트가 필요하다.

수량 기준은 COUNT/TOTAL(판매 포장 수), 개당 수량은 COUNT/PACK(한 포장 내용물 수), 중량·용량은 WEIGHT·VOLUME/ITEM이다. 정확한 본품 대응과 모든 후보의 추출은 여전히 AI 판단이다. sourceReviews는 출처 검토 누락을 검출하지만 AI가 NO_RELEVANT_FACT로 잘못 선언한 사실까지 서버가 모두 발견하지는 못한다.

근거 구조가 출력량을 늘리므로 기존 4096 출력 상한에서 큰 요청의 잘림 위험이 있다. 추가 AI 호출·출력 상한 확대·요청 분할은 섞지 않는다. 알 수 없는 단위·구조는 추정 승인하지 않고 검토로 보낸다. 단위 설정을 임의로 추가하지 않는다.
