# 오승인 차단 1차 영향 분석

작성일: 2026-10-28 · 단계: 영향분석 · 범위: 실제 AI 승인과 FULL 프롬프트 · 위험도: 높음

실제 경로는 PurchaseOptionAiService → AiInferenceValidator 및 PurchaseOptionInferenceService → ResultValidator다. 두 실제 AI 경로에 validateAiProposal을 사용하고 모의 추출은 기존 validateProposal을 유지한다.

추가 의미 계약은 AI가 선언한 피연산자 단위·값·근거만 검사한다. 단위가 설정된 출력 중 알려진 개수 단위에 대해 모든 피연산자가 알려진 물리 단위인 경우를 차단한다. 단위 미설정·미지 단위·계산 정보 누락은 임의 추정하지 않는다. 따라서 모든 의미 오류를 차단하지는 못한다.

사용 인원은 양의 숫자 또는 일부 한국어 인원 표현을 요구한다. 모델명은 R-R-/R-C-/MSIP- 형식과 인증번호·등록번호 근거가 함께 있을 때만 차단한다. 일반 문자열 전체에 과도한 규칙을 적용하지 않는다.

FULL R5/R9를 보강하고 버전을 v28로 변경한다. LIGHT, 사용자 프롬프트, JSON Schema, 파싱·정규화 계약은 그대로 유지한다. LIGHT 검증 실패 시 FULL 1회라는 기존 상한을 유지한다. 인증·요청 제한·DTO·외부 API 필드 변경은 없다.

주요 위험은 정상 응답 반려 증가와 프롬프트 변화에 따른 실제 AI 품질 변동이다. 관련 테스트 후 전체 Java 회귀, 저장 제안 재판정으로 전자를 확인하고 후자는 배포 승인 후 동일·미사용 표본으로 별도 비교한다.
