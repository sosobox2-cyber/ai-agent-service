# v42 반영·운영 배포

- 작성일: 2026-10-28 (Asia/Seoul)
- 요구사항: 작업 트리의 v42 변경 검토, 버전 반영, 필수 회귀, 의미별 커밋, Railway 배포와 무과금 확인.
- 사용자 지시로 배포·커밋·푸시가 승인됐다. 실제 OpenAI 호출, 예산 원장·인증·제한 설정 변경은 제외한다.
- 사용자가 지정한 단일 보고서 경로에 실제 수행한 단계만 기록한다.

## 요구사항·영향 분석

`application.yml`의 `app.inference.prompt-version` 한 줄을 `coupang-option-v41`에서 `coupang-option-v42`로 변경했다. 프롬프트 문구는 기존 v41과 동일하며, 이미 작성된 서버 보정 표시·포장식 범위 확장과 평가 도구를 함께 배포한다. 공통 검증·응답 필드와 운영 재배포에 영향을 주므로 전체 회귀와 데이터셋 백업·복원을 필수 조건으로 삼았다.

### 다른 세션 변경의 포함 판단

- `AGENTS.md`, `.agents/skills/ai-agent-change-workflow/SKILL.md`, `docs/agents/*`, `docs/report/report-guide.md`와 하네스 보고서는 별도 문서 커밋으로 포함한다. 실제 수량 검증·`serverNormalization`을 설명하고 위험 판정·실패 처리·사용자 변경 보존을 보완한 내용이며 운영 설정을 바꾸지 않는다. 이전 사용자 요청으로 작성한 Sync 기준 하네스도 이 범위다.
- 서버 보정 코드·관련 Java 테스트·API/운영 문서·소스 지도와 기존 서버 보정 보고서는 기능 단위로 포함한다.
- `eval-diverse.cjs`, `eval-metrics.cjs`, 관련 Node 테스트와 고정 평가셋 보고서는 평가 도구 단위로 포함한다. 원장의 실제 내용과 고정셋 원문은 Git에 넣지 않는다.
- `README.md~`, `pom.xml~`, `.run/*.xml`, `.claude/settings.json`, `target/`, `logs/`는 제외한다. 제외 파일과 예산 원장은 작업 전후 해시로 확인한다.

## 검증

기본 `java -version`은 Java 8이었고 `mvn`은 PATH에 없었다. 명령 프로세스에서만 아래 도구 경로를 지정했다. 저장소에 Maven Wrapper를 추가하지 않았다.

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17.0.2'
$env:Path="$env:JAVA_HOME\bin;D:\IntelliJ IDEA 2026.2.1\plugins\maven-plugin\lib\maven3\bin;$env:Path"
$env:OPENAI_RUN_COST_COMPARISON='false'
$env:OPENAI_API_KEY=''
java -version
mvn -version
mvn test
mvn package
node --test src/test/js/*.test.cjs
git diff --check
```

| 항목 | 실제 결과 |
| --- | --- |
| 도구 | Java 17.0.2, Maven 3.9.16, Node 24.19.0 |
| `mvn test` | BUILD SUCCESS, 317개: 통과 313·실패 0·오류 0·건너뜀 4 |
| `mvn package` | BUILD SUCCESS, 동일 회귀 통과, 실행 JAR 생성 |
| Node 전체 테스트 | 21개 통과, 실패·건너뜀 0 |
| `git diff --check` | 통과, LF→CRLF 안내만 출력 |

조건부 건너뜀은 실제 유료 호출 비교 1개와 `evaluation.replay.dir` 미지정으로 비활성인 저장 응답 재검증 3개다. 실제 키를 주입하지 않았고 실제 OpenAI 호출을 실행하지 않았다.

## 배포 전 백업·커밋

`git fetch origin`으로 원격 상태를 확인했다. Railway 서비스는 `main` 연결, 기존 배포 `587fe215-3cd9-4d73-9865-6e4acb69611a`의 v41이며 영구 볼륨과 미적용 변경이 없다. 기존 절차대로 코드 커밋을 `origin/main`에 한 번 푸시해 자동 배포한다.

```powershell
node logs/deploy-v42-20261028/backup.cjs
```

배포 전 데이터셋 2개를 ZIP으로 백업하고 모든 ZIP 항목이 읽히는지 확인했다. 원본·실행·검토 자료는 Git 제외 `logs/deploy-v42-20261028/`에만 저장한다. 백업 파일별 항목 수는 354개와 6개다.

| 커밋 | 내용 |
| --- | --- |
| `31b82c1` | 서버 보정 출처 표시와 포장식 인식 범위 확장 |
| `4753398` | 고정 평가셋과 버전별 판정 지표 집계 추가 |
| `a6573f6` | Sync 기준 에이전트 하네스와 역할별 검증 지침 정리 |
| `407ca6b` | 프롬프트 버전 coupang-option-v42 반영 |

`git push origin main` 성공: `9b36d81..407ca6b`. 기존에 로컬 커밋돼 있던 `3d34a2d`(운영 평가 하네스 결과 보고서 정리)도 함께 반영됐다. 배포 결과 보고서는 추가 자동 배포·데이터셋 초기화를 피하기 위해 배포 후 로컬 커밋으로 마무리하고 별도로 푸시하지 않는다.

## 배포 후 확인

Railway 배포 `558f6a67-b794-4da6-a5c2-bc5c3f6071dc`는 **SUCCESS**다. 배포 커밋은 `407ca6b545f1bfd8e3c19cbf6ee098926f809a67`, 생성 시각은 2026-10-28 16:28:54 KST, 성공 시각은 16:29:45 KST다. Railway 연결 도구의 `railway_list_deployments`와 `railway_get_status`로 확인했고 미적용 변경·추가 배포는 없다.

```powershell
git push origin main
node logs/deploy-v42-20261028/restore.cjs
```

`restore.cjs`는 먼저 `/api/v1/coupang/purchase-options/infer?testMode=true`에 예제 요청을 한 번 보냈다. `promptVersion=coupang-option-v42`, `inferenceSource=TEST`, `errorCode=TEST_MODE`, `success=false`, `autoApplyCandidate=false`, `aiUsage=[]`를 확인했다. 실제 추론 API를 AI 모드로 호출하지 않았다.

배포 후 데이터셋 목록이 비어 있어, 기존 백업 가져오기 API로 두 데이터셋을 복원하고 복원본 ZIP을 다시 내려받았다. 각각 10,270상품·44,898기준 행이 유지된다. 홈페이지는 HTTP 200이다.

| 배포 전 ID | 복원 ID | 비교 파일 | 변경·추가 |
| --- | --- | ---: | ---: |
| `32deb28e-713d-45d7-9869-c98be091da73` | `74df8638-d622-498b-a242-f894e581c2e2` | 353 | 0·0 |
| `14c3f2ee-247d-47a3-ab2c-903977a680b0` | `84e47786-1f20-4907-8c94-d99622688e4f` | 5 | 0·0 |

원본·실행·최신 결과·검토·검토 이력 **358개 파일**을 SHA-256으로 비교했다. 복원 계약상 바뀌는 데이터셋 ID와 가져온 시각을 제외한 메타데이터도 동일하다. 검토 이력은 파일명 재생성을 허용하되 내용 해시와 중복 개수까지 대조했다. 증거는 `preservation.json`, `restored.json`, `restore-journal.jsonl`, `smoke.json`과 원본·복원 ZIP에 남겼다.

기존 `verify.ps1` 직접 호출은 Windows 실행 정책 때문에 차단됐다. 정책을 변경하지 않고 동일 검사를 PowerShell 콘솔에서 직접 실행해 완료했다. 콘솔의 `Read-ArchiveIndex` 함수는 `ZipFile.OpenRead`로 각 파일의 바이트 해시를 만들고, `metadata.json`의 `id`·`importedAt`을 제외한 속성과 양쪽 파일 집합을 비교했다. 스크립트 호출 실패를 비교 성공으로 간주하지 않았다.

예산 원장과 제외 파일은 `Get-FileHash -Algorithm SHA256`으로 작업 전후 동일함을 확인했다. 인증·요청 제한 설정 변경과 실제 OpenAI 호출은 **0건**, 추가 AI 비용은 **$0**이다. 빌드·Node 로그와 보호 파일 해시는 Git 제외 배포 폴더에 있다.

## 확인하지 못한 항목

- v42 새 표기의 운영 AI 생성 정확성과 고정 평가셋의 유료 실행은 사용자 금지 범위이므로 수행하지 않았다.
- 조건부 건너뜀 4개는 위 검증 절에 구분했다.
- 영구 볼륨은 여전히 없으며 이번 배포의 데이터 보존은 백업·복원으로 확인했다.

## 교차 검토

동일 에이전트가 최종 diff·호출 경로·회귀 결과를 검토했다. 독립 리뷰는 수행하지 않았다. AI가 제출한 `serverNormalization`을 제거하는 파싱, 서버 보정 표시의 응답 전달, 포장식 정규식 공유와 기본 생성자 호환을 확인했다. 운영에서 새 표기의 실제 AI 생성 정확성은 미검증이다.
