# 오승인 차단 1차 교차 검토

작성일: 2026-10-28 · 단계: 교차검증 · 수행: 동일 에이전트 자체 검토, 독립 리뷰 아님

- 실제 AI의 재추론 판단과 최종 승인 모두 validateAiProposal을 호출한다. 모의 추출은 기존 validateProposal을 사용한다. 최종 승인·반려 제안 보존은 서비스 경로 테스트로 확인했다.
- JSON Schema·파싱·LIGHT·사용자 프롬프트는 변경하지 않았다. FULL의 R5/R9와 버전 v28을 변경했고 기존 LIGHT/FULL Schema 및 재추론 테스트를 포함한 전체 회귀가 통과했다.
- 검토 중 사용 인원에 숫자가 포함되기만 하면 음수·소수·모델명도 통과할 수 있음을 발견했다. 전체 문자열 형식 검사로 보완하고 PLUS8, -2명, 0.5명 반려와 범위·최대·이상 및 한국어 인원 표현 유지 테스트를 추가했다.
- 물리량 차단은 알려진 단위만 사용하고 원문 숫자를 비교·재계산하지 않는다. 미설정 단위에 기본값을 붙이지 않는다. 누락·미지 단위 등 검사 범위 밖은 별도 한계로 기록했다.
- 실제 저장 제안 93회 중 승인 변경은 사전 확인된 오류 4상품·7회뿐이다. 나머지 승인 유지가 모두 정확하다는 뜻은 아니다. 충돌 사례 등 미수정 오류가 남는다.
- 기존 등록 기준에 오류가 있어 기준 문자열 일치율 대신 오류 유형별 판정과 정상 대조군 유지로 비교했다. 새 기준은 에이전트 검토 기준이며 사람의 정답 확정을 대신하지 않는다.
- 실제 상품 본문·키를 새 추적 파일에 복사하지 않았다. 기존 사용자 IDE 설정·백업·이전 평가 자료는 보존했고 운영 서버·검토 데이터는 변경하지 않았다.
- 전체 Java 회귀와 실행 JAR 패키징 성공. 실제 AI 프롬프트 개선율, 미사용 표본의 오탐률, 운영 적용 효과는 미검증이다.

후속 배포에는 AGENTS.md의 “서버 배포·운영 업데이트는 사용자가 명시적으로 지시한 경우에만 수행한다”를 적용한다. 기존 운영 검토 메모 저장에 대한 자동 승인 검토 거절은 별개이며 이번 작업에서 재시도하지 않았다.
