# 서버 보정 출처 표시와 포장식 인식 범위 정리

- 작성일: 2026-10-28 (Asia/Seoul)
- 수행 단계: 요구사항 → 영향 분석 → 구현 → 테스트 (교차 리뷰는 같은 에이전트가 수행했으므로 독립 리뷰가 아님)
- 배경: 오늘 v28~v41 작업 검토에서 세 가지를 확인했다. ① AGENTS.md의 "원문 대조·재계산 안 함" 원칙과 실제 수량 검증 코드가 맞지 않았다. ② 포장식 정규식이 한 상품 형식에 맞춰져 있었고 두 파일에 중복돼 있었다. ③ 서버가 만들거나 바꾼 매핑을 응답에서 구분할 수 없었다.

## 요구사항
1. 문서·주석이 실제 동작과 같아야 한다. 수량 계열만 원문 대조를 하고, 포장당 용량만 서버가 계산한다.
2. 포장식 인식 범위를 표로 정한다. 하나의 정규식을 계산(`PackCapacityNormalizer`)과 계층 혼합 반려(`ResultValidator`)가 함께 쓴다.
3. 서버가 생성하거나 변경한 매핑에 `serverNormalization`을 표시한다. AI가 이 필드를 보내면 무시한다. 기존 응답과의 호환을 위해 값이 없으면 필드를 출력하지 않는다.

## 영향 분석 (위험도: 중간)
- 승인 조건은 바꾸지 않았다. 다만 포장식 문법이 넓어져 `ResultValidator`의 `QUANTITY_LEVEL_MISMATCH` 반려와 서버 계산의 적용 대상이 함께 늘었다. 반려 대상은 공백 구분, `입` 접미사, `봉` 단위다.
- API에는 필드만 추가했다. `OptionMapping`, `AiAssessment.ProposedMapping`, `MappingProposal.Entry`에 `serverNormalization`이 붙고 `NON_NULL`이라 값이 없으면 출력되지 않는다. 기존 생성자는 유지했다.
- 프롬프트·스키마는 변경하지 않았다. 프롬프트 버전(v41)도 올리지 않았다.

## 구현
- `MappingProposal.Entry.serverNormalization`을 추가했다. 규칙 이름은 `UNIT_DISPLAY`, `IMPLICIT_SINGLE_QUANTITY`, `PACK_CAPACITY`, `PACK_COUNT_EVIDENCE`다.
- `PurchaseOptionAiService.parse`가 AI 응답의 `serverNormalization`을 지운다.
- `CountUnitNormalizer`는 값이나 출력 단위가 실제로 바뀐 경우에만 표시를 붙인다.
- `PackCapacityNormalizer.EXPRESSION`을 확장했다. 항목 사이 공백, `입` 접미사, 내용 단위 `봉`을 인식한다. `ResultValidator`에 있던 중복 정규식은 지우고 이 정규식을 쓴다.
- 수정한 문서: AGENTS.md(작업 중이던 다른 수정은 유지하고 표시 규칙 한 줄만 추가), `ai-operations.md`(지원 범위 표), `api-reference.md`, `project-flow.md`, `source-reading-guide.md`, `AiValueContract` 주석.

## 테스트
실제 OpenAI 호출은 하지 않았고 비용도 발생하지 않았다. JDK 17.0.2, Maven 3.8.3을 오프라인으로 사용했다.
- `mvn -o test`: BUILD SUCCESS.
- `mvn -o test -Dtest=PackCapacityNormalizerTest,ImplicitSingleQuantityPolicyTest,AiAdapterTest,InferenceServiceTest,AiFailoverTest,PurchaseOptionApiTest`: 114개 실행, 실패 0, 건너뜀 0.
- 새 테스트:
  - 공백·`입`·`봉` 포장식이 계산·승인되는지
  - 순서가 다르거나 포장식이 여러 개면 정규화하지 않는지
  - 응답 두 곳에 `PACK_CAPACITY` 표시가 붙는지
  - `IMPLICIT_SINGLE_QUANTITY`·`UNIT_DISPLAY` 표시가 붙는지
  - AI가 보낸 `serverNormalization`이 지워지는지

## 남은 위험
- 중량 포장식(`50g×10개×3박스`)은 업무 기준을 확인하지 않아 계산하지 않는다.
- 새로 인식하는 표기(공백·`입`·`봉`)는 운영 AI로 확인하지 않았다.
- 웹 화면에는 `serverNormalization` 표시를 추가하지 않았다.
