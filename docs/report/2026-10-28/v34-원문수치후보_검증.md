# 원문 수치 후보 단계 v34 검증

작성일: 2026-10-28 · 영향: 실제 AI 입력, FULL 수량 계열만 · 위험도: 높음

## 요구사항과 변경

v33 짧은 시스템 지침은 정상 상품 3건을 모두 반려시켜 롤백했다. v32의 검증·프롬프트를 유지하면서 서버가 실제 원문에서 숫자와 단위의 연속 문자열을 먼저 추출한다. AI 입력에는 `sourceHints`를 별도 목록으로 넣어 출처·인용문·수치·단위·잠정 계층을 알려준다. 후보는 정답이 아니며 본품·사은품과 계층은 AI가 원문을 보고 판단한다. 기존 서버의 인용·충돌·단위 검증을 거쳐야 승인된다.

매·팩·롤·박스·정·캡슐·포·병·개·세트와 요청 대상인 중량·용량 단위를 추출한다. 길이 250M는 후보에서 제외한다. 8개 이하 단품에서만 최대 32개를 보내 입력 크기를 제한한다. 기존 상품 JSON, 외부 API 응답, 모의 추출·LIGHT 경로는 유지한다.

## 검증·교차 검토

후보 추출 테스트는 `70매x10팩`, `9매x4팩` 대 `9매x3팩`, `250M x 4롤 x 4팩`에서 양쪽 출처 수치를 보존하고 길이를 제외하는지 확인한다. AI 호출 계약과 기존 화면·예산 원장 테스트, Java 전체 회귀를 확인한다. 배포 후 기존 정상 상품과 출처 충돌·혼합 상품을 소규모로 재평가해 실제 품질을 판정한다.

정규식 후보에 없는 표현과 본품 대응의 완전성은 보장되지 않는다. 잘못된 후보가 있더라도 원문 인용 검사와 승인 규칙은 그대로 적용된다. 상품 원문과 실행 응답은 Git 제외 이력에만 저장한다.
