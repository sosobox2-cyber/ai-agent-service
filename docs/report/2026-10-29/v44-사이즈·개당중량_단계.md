## 요구사항과 영향 분석

사용자가 확정한 120상품·299검토행 스냅샷 `logs/diverse-eval-20261028/reviewed-snapshot-gold150-v43-final.json`을 사용한다. v43 gold150의 저장 AI 응답 149건을 재생하고 `eval-metrics.cjs.rescore`와 `classify(..., true)`로 확정값 기준 정오를 판단한다. 미확정 행이나 원래 등록값을 정답으로 추정하지 않는다.

사이즈 검증은 허용 대상명에 `사이즈`가 들어가고 단품명 또는 상품명에 하나의 명시 사이즈가 있는 경우에만 누락·불일치를 반려한다. 서버는 값을 보충하지 않는다. 전체 허용 옵션을 필수로 바꾸거나 고시의 여러 사이즈에서 하나를 고르지 않는다. 중량·용량은 FULL 지침에서 판매 단위 하나 기준을 정의하되 서버 중량 계산과 Schema는 확장하지 않는다. LIGHT는 변경하지 않는다.

위험도는 **높음**이다. `PurchaseOptionAiService → AiInferenceValidator → ResultValidator.validateAiProposal → AiValueContract`와 `PurchaseOptionInferenceService.assess → ResultValidator`의 실제 AI 승인에 영향을 준다. 새 의미 검사는 모의 `validateProposal`에 적용되지 않는다. 검증 실패는 기존 `RESULT_VALIDATION_FAILED`, success/autoApplyCandidate=false, 빈 최종 매핑·items와 aiAssessment 보존을 따른다. LIGHT 의미 검증 실패는 기존 FULL 한 번 전환 대상이 될 수 있으나 전환 한도·통신 오류·confidence·usage 정책은 바꾸지 않는다.

회귀 범위는 유일/여러 사이즈, 단품 우선과 대응 불명확, 라벨 별칭, 모델명 숫자·알파벳, 매트·가방 치수, FREE, 기존 침구 정답 승인, 승인·보안·재추론·프롬프트/Schema 전체다. 실 AI 대신 대역과 고정 저장 응답으로 검증한다.

## 구현

### 서버 사이즈 검증

`AiValueContract`에서 새 `ExplicitSizeValidator`를 호출한다. 이름에 사이즈가 있는 허용 대상별로 다음을 확인한다.

- 단품명의 유일한 명시 사이즈를 우선한다. 단품명에 여러 사이즈가 있으면 검사하지 않는다. 단품명에 사이즈가 없고 상품명에 하나만 있으면 공통 후보로 삼되, 다른 단품에 다른 사이즈가 있으면 공통 적용을 강제하지 않는다.
- 싱글/S, 슈퍼싱글/SS, 퀸/Q, 킹/K, 슈퍼킹/SK, 라지킹/LK, 더블/D, 패밀리/FAMILY, FREE/프리와 의류 문자 사이즈를 인식한다. 한글 최장 단어와 영문·숫자 경계를 사용해 모델명의 S100, 940S, 품명 내부 일부를 임의 사이즈로 보지 않는다. 기저귀 대상의 대형·중형·소형·특대형은 문자 크기와 연결한다. 일반 잡화의 대형이라는 수식어까지 강제하지 않는다.
- `킹(K)`처럼 같은 사이즈 별칭 병기는 하나로 인정한다. 기존 정답 `55/S`, `S(90)`도 유지한다. 다른 사이즈·복수 사이즈·물리 치수는 유일한 명시 라벨을 대신할 수 없다.
- 매핑이 없으면 `SIZE_VALUE_REQUIRED`, 명시 라벨과 다르면 `SIZE_VALUE_INVALID`다. 서버는 매핑이나 serverNormalization을 새로 만들지 않는다.
- 매트 대상의 고시에 실제로 존재하는 물리 치수는 허용한다. c10140의 1400*1800 (±20mm)는 승인 유지된다. 가방 치수33x20cm는 유일한 라벨을 강제할 근거가 없어 기존 허용을 유지한다. c00871의 FREE는 누락을 반려하고 FREE를 제출한 정상 제안은 승인한다.

보수적으로 제외한 사례도 남겼다. c02575는 상품명·단품명에 유일한 사이즈가 없고 고시에 여러 사이즈만 있으므로, 사용자 확정값이 첫 사이즈 싱글이어도 서버가 이를 추정하지 않는다. c01527의 치수 생략과 c05349의 고시에만 있는 슈퍼킹 생략도 이번 범위 밖이다. 최초 재생 중 c05349의 상품명 앞 `(SK)`가 슈퍼킹으로 잡히는 것을 확인했다. 판매 채널 표기일 수 있어 명확하지 않으므로 브랜드 접두사 뒤 상품명 앞의 `(SK)`를 공통 사이즈 근거에서 제외하고 회귀 테스트를 추가했다. 상품별 ID 특례는 없다.

### FULL의 판매 단위 지침

FULL R6에 판매 단위 하나 기준과 40g×30포×3박스→1200g, 16g×30봉/1박스→480g 예시를 추가했다. CONVERT 문구와 R7의 본품 한 개 표현을 판매 단위 기준으로 맞췄다. R9의 전체 합계 금지는 여러 판매 포장·서로 다른 제품의 합계로 범위를 명확히 해, 동일 본품의 판매 포장 하나 기준과 충돌하지 않도록 했다. 수산물 중량이라는 별도 대상의 R8 개체 기준은 유지한다.

`PackCapacityNormalizer`는 기존 50ml×30포×4세트→1500ml와 같은 판매 단위 원칙을 적용하지만 용량 전용이다. **중량 자동 계산을 추가하지 않았다.** 현행 Schema·QuantityEvidence·계산 계약으로 결과를 설명할 수 없을 때 계산 결과를 원문 fact로 위조하거나 반복 SUM하지 않고 생략·certain=false를 요청하도록 명시했다. 원문에 포장당 총중량이 명시된 c07901 같은 경우와, 명시 총중량이 없어 기존 계약으로 설명하기 어려운 경우를 구분한다.

Schema는 그대로다. 향후 중량의 포장당 곱셈을 자동 승인하려면 원문 낱개 중량·내용 개수와 파생 포장 중량을 구분하는 연산·계층 계약 검토가 필요하다는 제안만 남긴다. 이번에는 구현하지 않았다. LIGHT·사용자 프롬프트도 그대로다.

### v44 버전과 문서

`application.yml`은 coupang-option-v44로 올렸다. eval-diverse.cjs 허용 버전 목록에 v44를 추가하고 Node 테스트는 v44를 허용·v45를 미검증 버전으로 검사한다. ai-operations.md와 api-reference.md에 사이즈 오류 코드·판매 단위 지침·미검증 범위를 짧게 적었다.

## 별도 관점 검토와 미검증 범위

같은 에이전트가 최종 diff를 누락·과잉 차단 관점에서 검토했다. 독립 리뷰는 아니다. checkCoverage 전량 생략 정책, 수량 승인·정규화·재추론 상한, API 필드, Schema, LIGHT, 미설정 단위, 로그·비용 처리는 변경하지 않았다. 사이즈 값 보완이나 caseId 조건도 없다.

매트 고시 치수, 가방 치수, FREE, 명확한 의류 호수/문자 병기, 여러 사이즈와 부분 대응을 테스트했다. `(SK)` 채널 표기 혼동을 수정했고 최종 정답 승인 손실은 0이다. 아직 사전에 없는 사이즈 어휘·경계 표기나 고시에만 있는 사이즈를 완전하게 판단하지 않는다.

실제 AI의 FULL 중량 지침 준수·프롬프트 변경에 따른 응답 길이·비용·생성 품질은 미검증이다. 현행 중량 계산 계약으로 표현할 수 없는 포장 구성은 올바른 값이어도 검토될 수 있다. 오승인 8건이 남고 허용 옵션 생략 정책 전체는 사용자 결정 영역으로 유지한다. 배포·실제 호출·운영 평가 쓰기·원장·확정값 변경은 수행하지 않았다.

## Claude 교차 검토 후 보완

전체 데이터셋(`cases.jsonl`, 사이즈 대상 기준 행 14,990개)에 같은 규칙을 적용해 "등록값을 AI 값으로 냈다면 반려되는지"를 셌다. gold150 재생에는 드러나지 않은 오반려 패턴 두 가지가 있었다.

1. **상품명 대체가 의류·잡화에도 적용됨.** 단품명에 사이즈 문자가 없으면 상품명에서 찾는데, 다음을 사이즈로 오인했다. 침구 외 128상품·206행에서 정상 값이 반려될 수 있었다.
   - "울 더블 버튼 코트" → 더블
   - "20 SS" 시즌 표기 → 슈퍼싱글
   - 판매처 "SK 스토아" → 슈퍼킹
   - 단품명 "다크네이비/55"의 숫자 사이즈를 무시하고 상품명으로 넘어감
2. **단품명 "90(S)", "100(L)"에서 AI가 숫자 쪽("90")을 내면 반려됨.**

수정 내용:
- 상품명 대체는 침구·매트·기저귀 대상에만 적용한다.
- 단품명에 2~3자리 숫자 사이즈가 있으면 상품명을 쓰지 않는다.
- `SK스토아` 표기를 제외한다.
- 단품명의 숫자 사이즈 조각을 그대로 옮긴 값은 인정한다. 색상 같은 다른 조각은 인정하지 않는다.
- 회귀 테스트: `ExplicitSizeValidatorTest.doesNotTakeApparelOrGoodsSizeFromProductNameWords`
