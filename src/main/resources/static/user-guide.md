# AI Agent Service 소개와 사용 안내

이 문서는 상품 운영 담당자, 기획자 등 개발 지식 없이 서비스를 이해하고 시험해 보고 싶은 분들을 위한 안내입니다. 먼저 사용 방법을 확인하고, 기술 사양은 필요한 경우 참고하세요.

## 1. 어떤 일을 하는 서비스인가요?

SK스토아 상품의 단품 옵션명을 읽고, 쿠팡에서 사용하는 구매옵션 항목에 맞춰 값을 나누어 주는 서비스입니다.

| 원본 단품 옵션명 | 쿠팡 구매옵션명 | 추출한 값 |
|---|---|---|
| 블랙/90 | 패션의류/잡화 사이즈 | 90 |
| 블랙/90 | 색상 | 블랙 |

사람이 옵션명을 하나씩 읽고 색상과 사이즈를 나누는 작업을 돕습니다. 현재는 결과 확인까지 제공하며 쿠팡에 상품을 등록하거나 기존 상품을 수정하지는 않습니다.

## 2. 왜 필요한가요?

판매처마다 상품 옵션을 표현하는 방식이 다릅니다. 한 곳에서는 색상과 사이즈를 한 문장으로 표시하고, 다른 곳에서는 별도 항목으로 입력해야 할 수 있습니다.

이 서비스는 원본 표현에서 항목별 값을 제안하고, 단품 매핑 누락이나 중복 조합을 검사하여 반복 작업과 결과 검토를 지원합니다. 실제 업무 시간 절감이나 전체 상품의 추론 정확도는 아직 측정하지 않았습니다.

## 3. 어떻게 판단하나요?

1. 상품명, 브랜드, 카테고리, 단품 옵션명, 허용 구매옵션명과 선택 입력인 상품정보고시·기술서 구성을 받습니다.
2. AI가 각 단품의 옵션명을 읽고 허용된 구매옵션에 맞는 값을 제안합니다.
3. 프로그램이 응답 형식, 허용 이름, 단품 누락, 중복 매핑, 단위 설정과 최종 조합을 검사합니다.
4. 최종 단품 결과와 AI·서버의 판단 사유를 보여줍니다. 조건을 통과한 결과는 자동 적용 후보로 표시합니다.

색상·사이즈처럼 단순한 상품은 간단한 방식으로 분석하고, 수량 계산처럼 복잡한 상품은 처음부터 자세히 분석합니다. 자동 적용 후보는 다음 업무 단계에서 사용할 수 있는 결과라는 뜻이며, 실제 쿠팡 등록을 실행한다는 뜻은 아닙니다.

### 자동으로 다시 분석하는 경우

간단한 분석에서 AI가 값을 확실하게 정하지 못하거나 일부 단품을 빠뜨리는 등 결과에 문제가 있으면, 프로그램이 같은 상품 정보를 더 자세한 방식으로 한 번 더 분석합니다. **별도의 버튼을 누를 필요 없이 결과가 나올 때까지 기다리면 됩니다.**

| 상황 | 처리 방법 |
|---|---|
| 간단한 분석으로 결과를 얻은 경우 | 한 번 분석한 결과를 확인합니다. |
| 간단한 분석 결과에 문제가 있는 경우 | 자세한 방식으로 한 번 더 분석합니다. 총 두 번을 넘기지 않습니다. |
| 처음부터 자세한 분석이 필요한 상품 | 한 번 분석합니다. 결과에 문제가 있어도 계속 반복하지 않습니다. |
| 연결 문제나 응답 지연 등으로 오류가 난 경우 | 분석을 멈추고 오류를 안내합니다. 표시된 사유를 담당자에게 전달하세요. |

다시 분석해도 결과를 사용하기 어렵다면 **검토 필요**로 표시하며 최종 결과 표가 비어 있을 수 있습니다. 이때는 **판단 사유**와 **확인할 항목**을 읽고, 입력한 옵션명에 색상·사이즈 등의 정보가 있는지, 단품을 빠뜨리거나 중복 입력하지 않았는지 확인하세요. 원인을 알기 어려우면 입력 내용과 표시된 사유를 담당자에게 전달하세요.

화면의 신뢰도 숫자가 낮다는 이유만으로 다시 분석하지는 않습니다. 추가 분석 없이 검토가 필요한 결과로 표시될 수도 있습니다.

한 번 더 분석하면 결과를 받기까지 시간이 더 걸리고 AI 사용 비용도 추가됩니다. 테스트 모드에서는 실제 AI를 호출하거나 다시 분석하지 않습니다.

### 상품정보고시의 역할

상품정보고시 아래의 **상품 기술서 · 구성 (선택)**을 클릭하면 입력란을 열고 닫을 수 있습니다. 기본은 접힌 상태입니다. 기술서의 구성 항목을 붙여 넣어 주세요. 예: `본품 선크림 50ml 7개 + 사은품 파우치 1개`. 입력 후 접어도 내용은 유지되고 요청에 포함됩니다. 생략해도 요청할 수 있으며, 입력하면 AI가 수량·용량·중량 판단의 참고 자료로 사용합니다. 본품과 사은품, 판매 세트 수와 한 세트의 내용물 수를 구분해 적어 주세요. 구성과 상품명·정보고시가 충돌하면 검토가 필요할 수 있습니다. 실제 정확도 개선 정도는 아직 측정하지 않았습니다.

상품정보고시는 옵션명의 의미와 상품 구성을 이해하는 참고 자료입니다. SK스토아의 항목명과 값을 긴 텍스트로 붙여 넣거나 줄바꿈하여 입력하면 됩니다.

```text
색상: 블랙
치수: S(90) / M(95) / L(100) / XL(105)
제조국: 베트남
```

원본 옵션명이 `블랙/90`이면 사이즈는 `90`입니다. 정보고시에 `S(90)`가 있어도 원본에 없는 `S`로 바꾸지 않습니다. 일반 색상·사이즈·핏은 원본 옵션명에 빠진 값을 상품정보고시만 보고 채우지 않습니다.

### 옵션명이 단일상품 또는 단품인 경우

단품이 하나이고 옵션명이 `단일상품` 또는 `단품`이면 실제 AI는 상품명과 상품정보고시를 근거로 수량·규격 등을 판단할 수 있습니다. 리르 패치 예제의 기대값은 다음과 같습니다.

| 구매옵션명 | 기대값 | 판단 근거 |
|---|---|---|
| 수량 | 9개 | 상품명에 본품 9박스로 표시 |
| 개당 수량 | 50개입 | 정보고시에 1박스: 5매, 총 50패치로 표시 |

무료체험분·사은품·증정품은 본품 계산에서 제외합니다. 구성이나 수량이 모호하면 검토가 필요한 결과로 반환할 수 있습니다.

## 4. 테스트 페이지 사용 방법

1. 테스트 페이지에서 **예제 불러오기**를 선택하거나 상품 정보를 직접 입력합니다.
2. **허용 구매옵션명**에 쿠팡 카테고리에서 허용하는 항목명을 입력합니다. 예: `패션의류/잡화 사이즈, 색상`.
3. **원본 단품 목록**에 각 `optionId`와 `optionName1`을 입력합니다. 단품 ID는 중복되지 않아야 합니다.
4. 필요한 경우 상품정보고시와 구매옵션별 단위 설정을 입력합니다.
5. 테스트 모드 또는 실제 AI 추론을 선택하고 요청을 보냅니다.
6. **최종 단품 결과**를 먼저 확인하고, AI·서버 판단과 검증 오류를 펼쳐 검토합니다.

요청 JSON과 응답 JSON 옆의 복사 아이콘으로 전체 데이터를 복사할 수 있습니다. 사용설명서는 페이지 상단에서 열 수 있습니다.

### 테스트 모드와 실제 AI 추론

| 구분 | 테스트 모드 | 실제 AI 추론 |
|---|---|---|
| AI 호출 | 없음 | OpenAI API 호출 |
| API 키 | 필요 없음 | 서버 환경에 설정 필요 |
| 판단 방식 | 지원하는 패턴의 제한적인 모의 추출 | AI가 원문과 상품 구성을 판단 |
| 결과 표시 | 모의 결과, `TEST_MODE` | 정상 결과 또는 검토·오류 결과 |
| 자동 적용 후보 | 항상 아니요 | 확실 판정·신뢰도·검증 조건 충족 시 예 |
| 토큰·비용 | 실제 AI 사용량 없음 | 응답에서 받은 사용량 표시 |

테스트 모드는 실제 AI 정확도를 평가하는 기능이 아닙니다. 지원하지 않는 표현은 결과가 없거나 검증에 실패할 수 있습니다. 실제 AI 호출에는 API 사용 비용이 발생합니다.

### 구매옵션별 단위 설정

단위 설정은 선택 입력이며 **허용 구매옵션명에 매핑**됩니다. 구매옵션명, 기본단위(`defaultUnit`), 단위 선택지(`unitOptions`)를 입력합니다.

| 설정 예 | 원문 | 결과 예 |
|---|---|---|
| 수량: 기본 개, 선택지 개·박스·세트 | 6박스 | 6박스 |
| 수량: 기본 개, 선택지 박스·세트 | 6병 | 6개 |
| 단위 설정 없음, 화면크기(cm) | 109cm | 109cm |
| 단위 설정 없음, 화면크기(in) | 43인치 | 43인치 |

기본단위는 원문 단위가 선택지에 없거나 단위를 판단하기 어려울 때 사용합니다. 기본단위가 선택지에 없어도 됩니다. 기본단위 적용은 숫자를 유지한 단위 표기이며 박스당 개수로 환산한다는 뜻은 아닙니다. 숫자 자체가 불명확하면 숫자를 만들어내지 않습니다.

설정하지 않은 구매옵션은 AI가 원문과 옵션 의미에서 판단한 값·단위를 그대로 사용합니다. 일부 옵션만 설정했다면 해당 옵션에만 단위 규칙을 적용합니다.

### 제공되는 예제

| 예제 | 상품 ID | 확인할 결과 |
|---|---|---|
| 아이그너 니트탑 | 68535109 | 네 단품의 블랙 및 90·95·100·105 |
| 리르 패치 | 64629042 | 수량 9개, 개당 수량 50개입 |
| 김소형 선크림 | 65578661 | 수량 7개, 개당 용량 50ml |
| 종가 김치 세트 | 65579064 | 수량 1세트, 개당 중량 5.2kg |
| 해즈픽 칫솔 세트 | 65592697 | 수량 1세트, 개당 수량 10매입 |
| 플럭스 TV | 50945478 | 화면크기 109cm·43인치·109cm(43인치) |

예제 값은 해당 입력의 기대 결과입니다. 실제 AI 응답은 달라질 수 있으므로 근거와 최종 결과를 확인하세요. TV 모의 추출은 명시된 화면크기만 처리하며 설치지원방식·스탠드/벽걸이 구분·모델명은 실제 AI로 확인합니다.

## 5. 결과와 신뢰도 읽는 방법

**최종 단품 결과**는 서버가 확인한 구매옵션 조합입니다. **AI·서버 판단 및 옵션 매핑 상세**에는 AI 제안과 서버의 승인·보류 이유가 있습니다. AI 제안에 값이 있어도 검증에 실패하면 최종 결과는 비어 있을 수 있습니다.

최종 신뢰도는 AI 전체 신뢰도와 개별 매핑 신뢰도 중 최솟값입니다.

```text
최종 신뢰도 = MIN(AI 전체 confidence, 각 매핑의 confidence)
예: MIN(0.95, 0.90, 0.85) = 0.85 → 화면에 85% 표시
```

자동 적용 후보가 되려면 다음 조건을 모두 만족해야 합니다.

- AI의 `certain=true`
- 최종 신뢰도가 서버 기준 이상: 현재 기본 기준 `0.80`
- 응답 형식·단품·허용 옵션명·설정된 단위·최종 조합 검증 통과

AI가 부여하는 confidence 자체에는 별도의 수학적 계산 공식이 없습니다. AI의 자체 평가값이며 **95%가 실제 정답 확률 95%를 의미하지는 않습니다.** 테스트 모드의 신뢰도는 0이며 정확도를 측정한 값이 아닙니다.

**낮은 신뢰도만으로 FULL을 추가 호출하지 않습니다.** 재추론 기준과 최종 자동 적용 기준은 별개입니다. 예를 들어 형식과 매핑 검증이 정상인 LIGHT 결과의 신뢰도가 0.50이면 재추론 없이 검토 필요로 반환합니다. 기존 자동 적용 기준 0.80은 유지합니다.

## 6. AI 호출·토큰 사용량 확인

최종 단품 결과 아래의 **AI 호출·토큰 사용량**을 펼치면 현재 요청의 정보를 확인할 수 있습니다.

| 표시 항목 | 의미 |
|---|---|
| 모드 | 사용한 LIGHT 또는 FULL 프롬프트 |
| 모델 | API 응답에 포함된 실제 모델명 |
| 입력 토큰 | 프롬프트·상품 정보 등 입력의 사용량 |
| 캐시 입력 | 입력 토큰 중 재사용된 부분. 입력에 이미 포함됨 |
| 출력 토큰 | AI가 생성한 응답의 사용량 |
| 총 토큰 | 해당 호출의 입력·출력 전체 사용량 |
| 예상 비용 | 지원 모델의 단가와 API 사용량으로 계산한 USD 추정 |

최초 LIGHT 호출과 FULL 재추론을 각각 표시하고 전체 합계를 제공합니다. 정상 LIGHT에는 재추론 비용이 없으며, LIGHT → FULL이 발생하면 최초 LIGHT 비용에 FULL 호출 비용과 추가 응답 대기 시간이 더해집니다. API가 수치를 제공하지 않으면 `확인 불가`로 표시하며 0으로 가정하지 않습니다. 실제 청구 비용은 캐시 사용, 가격과 과금 조건에 따라 달라질 수 있습니다. 테스트 모드는 실제 AI를 호출하지 않습니다. 사용량 표시는 콘솔 로그 활성화 여부와 관계없으며 API 키나 헤더는 표시하지 않습니다.

운영 담당자는 기본 경로 `logs/ai-usage.jsonl`에서 같은 `inferenceId`로 연결된 두 호출을 확인할 수 있습니다. FULL 호출 자체가 실패하면 화면의 오류 응답에 사용량이 없을 수 있지만, 먼저 수신한 LIGHT 사용량은 JSONL에 기록됩니다. API 명세서에는 응답의 `aiUsage` 필드와 재추론 사유 코드가 설명되어 있습니다.

## 9. AI 프롬프트 전달 방식

```text
상품 요청 JSON
  → LIGHT/FULL 선택
  → System 메시지 + User 메시지(지시문과 상품 JSON)
  → OpenAI Chat Completions
  → 서버 결과 검증
  → LIGHT 검증 실패 시 FULL로 1회 재추론 및 재검증
  → 최종 자동 적용 기준 확인 또는 검토 필요 반환
```

### System 메시지

확인된 색상·사이즈·핏 옵션만 포함하고 단위 설정이 없는 요청에는 LIGHT를 사용합니다. 수량·용량·중량 등 계산형 옵션, 단위 설정, 알 수 없는 옵션명, `단품/단일상품` 요청은 FULL을 사용합니다. 판단이 애매하면 FULL을 선택합니다.

기존 FULL 프롬프트를 보존하고 LIGHT를 별도 파일로 관리합니다. `AI_PROMPT_MODE=FULL`로 모든 요청에 기존 상세 프롬프트를 사용할 수 있습니다.

### User 메시지와 응답 형식

공통 지시문 뒤에 상품 요청 JSON을 `product`로 감싸 붙입니다. 아래는 전달 구조를 설명하기 위한 예시입니다. 실제 `schema`에는 요청별 허용 구매옵션명과 단품 ID 등을 정의한 JSON 객체가 들어갑니다.

```json
{
  "model": "gpt-4.1-mini",
  "temperature": 0,
  "max_tokens": 4096,
  "messages": [
    { "role": "system", "content": "선택된 LIGHT 또는 FULL 프롬프트" },
    { "role": "user", "content": "공통 지시문\n{\"product\": 상품 요청 JSON 전체}" }
  ],
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "purchase_option_mapping",
      "strict": true,
      "schema": "설명용 자리표시자: 실제 요청별 JSON Schema 객체"
    }
  }
}
```

LIGHT 검증이 실패하면 FULL System 메시지와 동일한 User 메시지·상품 JSON·JSON Schema로 새 요청을 한 번 보냅니다. 이전 AI 응답이나 누락 보정 지시는 덧붙이지 않습니다. PromptSelector는 최초 요청에서만 사용하고 재추론은 FULL을 직접 지정합니다. 응답 구조와 서버 검증은 두 모드에서 동일합니다.

## 10. 오류 처리

```text
OpenAI HTTP 오류 → SafeErrorHandler → InferenceException
시간 초과·통신 실패 → InferenceException
잘못된 요청 → RequestValidator / 요청 형식 검사
  → GlobalExceptionHandler → HTTP 상태 + InferenceResponse JSON

AI 응답 해석 오류·결과 검증 실패 → LIGHT만 FULL로 1회 재추론
최종 검토 필요 → 서비스 판단 결과로 HTTP 200 반환
```

| 상황 | 오류 코드 | HTTP 상태 |
|---|---|---|
| 실제 AI 호출 시 API 키 없음 | AI_NOT_CONFIGURED | 503 |
| OpenAI HTTP 429 | AI_RATE_LIMIT | 429 |
| OpenAI HTTP 408·504 또는 감지된 시간 초과 | AI_TIMEOUT | 504 |
| 그 밖의 외부 호출 실패 | AI_UPSTREAM_ERROR | 502 |
| AI 응답 JSON 해석 실패·응답 미완료 | 최종 실패 시 REVIEW_REQUIRED, 사유 INVALID_RESPONSE | 200 |
| 요청 조건 위반 | INVALID_REQUEST | 400 |
| 잘못된 요청 JSON | INVALID_JSON | 400 |
| 예상하지 못한 예외 | INTERNAL_ERROR | 500 |
| 테스트 모드 등의 결과 검증 실패 | RESULT_VALIDATION_FAILED | 200 |
| 실제 AI 최종 검증 실패·불확실·신뢰도 기준 미달 | REVIEW_REQUIRED | 200 |

결과 검증 실패와 검토 필요는 정상적으로 반환한 판단 결과입니다. 따라서 **HTTP 200이어도 success=false일 수 있습니다.** 호출자는 HTTP 상태와 함께 `success`, `autoApplyCandidate`, `errorCode`, `validationErrors`를 확인해야 합니다.

SafeErrorHandler는 외부 오류 응답의 본문과 헤더를 오류 메시지에 포함하지 않습니다. GlobalExceptionHandler는 요청 DTO 검증, JSON 해석, 매개변수 타입 오류도 처리합니다.

## 11. 요청과 응답 데이터의 역할

| 객체 / 필드 | 의미 |
|---|---|
| InferenceRequest | 상품 정보·정보고시, 허용 구매옵션명, 원본 단품 목록, 선택 단위 설정 |
| SourceOption | 단품 ID optionId와 원본 문자열 optionName1 |
| MappingProposal | AI 제안: certain, 전체 confidence, mappings, reason |
| MappingProposal.Entry | 단품 하나의 구매옵션명, 추출 값, 신뢰도·근거·계산 설명 |
| PurchaseOptionItem | 단품 ID와 구매옵션 Map으로 조립한 최종 결과 |
| OptionMapping | 원본 옵션명을 함께 담은 상세 매핑 |
| InferenceResponse | 성공 여부, 자동 적용 후보 여부, 최종 결과, 오류, AI·서버 판단, 사용량 |
| aiAssessment | 서버가 승인하거나 반려한 AI의 제안 |
| serverAssessment | 서버 승인·보류 이유와 신뢰도 기준 |
| aiUsage / AiCallUsage | 현재 요청의 실제 AI 호출별 토큰·캐시·예상 비용 |
| AiInferenceValidator / AiInferenceValidationResult | 재추론 판단에 사용하는 서버 검증과 오류 목록 |
| AiRetryReason | 재추론 사유 코드 |
| AiRetryProperties | 재추론 활성화 여부·최대 횟수·선택적 신뢰도 기준 |

AI 제안과 최종 결과를 구분하여 확인하세요. 검증 실패 시 AI 제안이 남아 있어도 `items`와 `optionMappings`는 비어 있을 수 있습니다.
